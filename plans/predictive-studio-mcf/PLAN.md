**The One-System View.** PS becomes a generative modeling system on one ontology: a registry of **typed components** (models, preprocessing, calibrators, adapters, explainers, transformations, sources, parameters, structures) wired under a **port contract** that makes composition legal-by-construction. Trees organize inheritable *wisdom* (banks/gates/priors per family); the type system owns *legality*. Agents design models through a metacognitive loop (node qualia → commit/defer/combine → branch-and-refine → recurring synthesis → story tagging); users author, approve, garden, ground, operate, curate. Every trained artifact becomes a reusable, meaning-grounded, story-tagged component. Connectors close the loop: data in → model judgment out to the org's real systems → intervention outcomes back on the next sync. The Cambrian explosion lives in the **search space**, governed by existing budget/leaderboard/prune machinery.

**Locked ontology (digest).** (1) Uniform registry, one `Kind` axis. (2) Typed ports; wiring legal on match or declared Adapter. (3) Pluggable (first-order) vs fillable (typed holes: Bagging(__), Boosting(__), Stacking(__,__,meta=__), Calibrator(__)); filled fillables are pluggable → recursion. (4) There-is-and-can-be: recipes downward; membership affordances **computed** from port compatibility (`findCompatibleSlots`/`findCompatibleFillers`), never enumerated. (5) Reusable ≠ trainable; hand-authored artifacts interchangeable with trained instances of the same port type. (6) Trained instances (immutable `MJ: ML Models`) referenceable apply-frozen inside new composites. (7) Meaning grounding: ports/parameters FK-bound to Entities/EntityFields; agents assign, users confirm. (8) Platform interop: embeddings→vector infra, cluster-ids→segments, probabilities→columns, states→attributes. (9) Two creation levels: hybrids (model-level, shared can-be parent) and created models (constitution-level via **motifs** — GLM = predictor+link+loss+penalty). (10) Trust asymmetry: new driver code gates on CodeApprovalStatus; composites are cheap pruned experiments.

**Pipeline (locked shape).** Grounded sources → invariant spine (one assembly path, as-of, leakage deny-list, locked holdout carved first — unviolable, outside the composable part) → preprocessing segment with **ordered typed positions** (impute→transform→scale→encode; ≤1 bank choice per position; legitimately empty per invariance facets) → model graph (leaf or composite DAG) → optional calibration position → output grounding. **Banks are indexed by (family × position)** — the pipeline decides the tree.

**Users (six permission-gated roles).** Author (build/define/save) · Approver (CodeApprovalStatus, promotion, queries, leakage sign-off) · Gardener (tenant tree/bank tending) · Groundskeeper (meaning FKs, deny-lists) · Operator (drift, challengers, pinning, schedules) · Librarian (story tags, nominal names, collections, sharing).

**MJ invariants (unviolable, every phase).** One assembly path; fit-once/apply-frozen travels in artifacts; locked holdout scored exactly once; model immutability; no auto-promotion; engines-once/thin-surfaces; metadata via mj-sync never SQL INSERTs; migration → CodeGen → typed code; no `any`; BaseSingleton/BaseEngine patterns.

**Two-tier testing (binding).** Testing is split into two tiers that must never be confused: **Tier 0 — idea validation** (ADDENDUM 5): cheap, pre-build experiments with falsifiable kill criteria that test whether the plan's contested BETS are true, run BEFORE the machinery that depends on them is built; and **Tier 1 — software verification** (the testing spine below + Addendum 2): the full program that tests whether the IMPLEMENTATION is correct, run as things are built. **Testing spine (all phases).** A shared **TestBench** package (`packages/AI/PredictiveStudio/TestBench/` + Python mirror `python/psgen/` installed into the sidecar venv) of seeded, deterministic generators that return `(data, truth)` — tests assert **recovery of planted structure**, never "it ran." Orthogonal dials compose over any base: `withMissing(MCAR|MAR|MNAR)`, `withLeakage(proxy)`, `withSkew`, `withOutliers`, `withCategorical(+OOV-at-predict)`. Determinism: required seed, single PRNG stream (mulberry32 + Box–Muller — the stack already proven in `live-train-score.integration.test.ts`), no Date.now/Math.random/uuid, fixed dial order recorded in a manifest; TS↔Python parity proven by committed byte-compared fixtures. # DOCUMENT 4 — Composition & Search: Executor, Tree, Strategist

**Objective.** Make composition real (train/score composite DAGs without violating a single invariant), stand up the tree(s) with banks per the study, and turn the experiment orchestrator into the tree-sampling search engine.

**1. Composite execution — the frozen cascade** (TS-side `CompositeTrainingExecutor`, `Engine/src/training/composite-training-executor.ts`; sidecar stays a stateless per-component kernel — lineage/validation/trust all live once, in TS):
- Carve locked holdout ONCE (existing `carveLockedHoldout`; time-ordered mode for T5/T6). Holdout rows never enter any node's `/train`.
- Topo-order (validated by `validateCompositeSpec`); per non-terminal node: `/train` on dev → `/predict` same dev rows with the frozen child → adapt outputs to columns per declared adapter → append to working dev matrix; separately `/predict` holdout rows apply-frozen → append same columns to working holdout matrix. **No component ever fits on holdout rows.**
- Terminal node: `/train` with augmented dev + forwarded augmented holdout — **holdout scored exactly once, at the terminal.**
- **Calibration exception (day one)**: calibrator nodes carry `fitOn:'upstream-validation-split'` — a calibration split carved off dev so a calibrator never fits on rows its upstream model fit on. (Known caveat, flagged: within-dev child-fit makes the terminal's *validation* metric mildly optimistic; the leaderboard ranks on the honest holdout. # ADDENDUM 4 — The AutoML Post-Mortem Discipline (effort rebalance; adopted from team feedback)

**Provenance.** Experienced-team feedback (2026-07): the AutoML graveyard is real (Google AutoML Tables, IBM AutoAI, SageMaker Autopilot's irrelevance, DataRobot's collapse, dozens of startups); the majority of effort must go to **data assembly, leakage control, p-hacking prevention, calibration, and monitoring — especially monitoring**; model selection is largely academic because gradient-boosted trees win tabular supervised anyway. This addendum ADOPTS that guidance. Nothing architectural changes — the corrections are to **effort weighting, rollout gating, and a standing audit checklist**.

## A4.1 The effort-priority statement (now binding)

The majority of build/tuning/hardening effort goes, in order, to: (1) **data assembly correctness** (one path, as-of, hydration guards), (2) **leakage control** (deny-lists, pre-train proxy screen, planted-leakage tests, dominance flags), (3) **p-hacking prevention** (locked holdout scored once + instrumentation; leaderboard discipline; no metric shopping), (4) **calibration** (first workstream, ECE floors, honesty invariants), (5) **monitoring** (prediction logs → momentum → drift → challenger → human-gated retrain; trajectory analytics; production surfaces). The component ontology, catalog, and search exist **in service of these**, not beside them. Any resourcing conflict resolves in this order.

## A4.2 Demand-driven driver gating (replaces schedule-driven tranches)

- **Activate first (the business-question set):** T1 GBT-class + linear + calibrators, T2 GLMs (effect sizes), T4 survival (time-to-lapse), T5 forecasting (dues/attendance), T7 CLV (BG/NBD family). These answer questions GBT structurally cannot.
- **Cataloged-but-dormant (Status='Planned') until a named use case pulls them:** T3 unsupervised (except cluster-as-feature when a chain needs it), T6 sequence-state beyond HMM, pattern mining, UMAP, GP, exotic baselines. A tranche activation requires a one-line justification recorded in the catalog row ("pulled by: <use case>").
- **Default agent search is NARROW:** GBT + one regularized linear + the dummy floor. Wide family search is opt-in per experiment, budget-gated, and the triage decision must cite a statistic to justify leaving the default set. (The 12-scenario evals already grade this — small-n and pure-noise scenarios hard-fail exotic wandering.)
- The catalog's breadth claim is reframed everywhere it appears: **task coverage + component feeds, not model-selection competition.** ~40 of the 58 exist because GBT cannot answer their question; ~15 tabular-supervised alternates exist as floors, interpretability options, and constitution parts.

## A4.3 The graveyard checklist (standing audit gate — every phase exit re-answers it)

# ADDENDUM 5 — PHASE 0: The Idea-Validation Program (test the BETS before building the machinery)

**Principle.** Every contested hypothesis in this plan gets a cheap, falsifiable experiment BEFORE the machinery that depends on it is built. Tier 0 tests *ideas*; the rest of the plan's testing (TestBench, matrices, invariants, evals) tests *software*. Nothing here requires the MCF migration, the catalog, or any new framework code — every experiment runs on **shipped PS** (the live sidecar with xgboost/lightgbm/logistic/rf/ridge/mlp, the existing locked-holdout machinery) plus standalone Python scripts (hmmlearn/sklearn/lifelines/implicit direct) and LLM calls. This is also, verbatim, the "smaller case tests reproducing known failure modes" committed to Arie — each experiment ends in a one-page memo, and the set ends in a verdict document shared with him.

## A5.0 The validation harness (build first, ~2–3 days, throwaway-grade)

`plans/predictive-studio-mcf/phase0/` — standalone scripts, deliberately NOT the production TestBench:
- **Seeded mini-generators** (the only TestBench preview needed): planted-logit classification, planted-coefficient regression, planted-HMM sequences, planted-cluster heterogeneity, planted-latent-factor interactions, planted-hazard survival with censoring dial, and the dials `withLeakage(proxy, realisticName)` + `withMissing`. Deterministic seeds; each returns `(data, truth)`.
- **A locked-holdout referee script**: carves the holdout once, hashes rows, trains/scores via the shipped sidecar or direct sklearn, scores holdout exactly once per experiment arm, logs everything to a JSONL audit file. No experiment may compute its own holdout number.
- **An LLM harness**: prompt templates + structured-output schemas for the agent-role experiments (V1, V4, V5), model + prompt checksums recorded per run.
- **A memo template**: hypothesis · method · N/seeds · result table · verdict (PASS / REVISE / KILL) · what it gates.

## A5.1 The experiments (V1–V8): hypothesis, method, kill criteria

**V1 — Semantic leakage detection (the "meaning catches what statistics can't" bet).**
- *Hypothesis:* an LLM reading only schema + column descriptions flags planted leakage that statistical screens miss, and the union beats either alone.
- *Method:* 30 seeded datasets across 3 leak classes — (a) direct proxies with realistic names (`InvoicePaidFlag` for renewal), (b) post-outcome timestamps (`CancellationProcessedAt`), (c) statistically-invisible leaks (a leak only detectable from its *name/semantics*, correlation deliberately dampened to <0.3) — plus 30 leak-free controls with suspicious-LOOKING names (decoys). Three arms: correlation screen (|r|>0.95), LLM-semantic screen (schema+descriptions only, never values), union.
- *Measured:* precision/recall per arm per class; decoy false-positive rate.
- *PASS:* LLM recall ≥0.8 on class (c) with decoy FPR ≤0.2, and union recall > statistical recall by ≥0.2 overall. *REVISE:* LLM catches (a)/(b) but not (c) → semantic screening still ships but claims narrow. *KILL:* LLM ≈ statistical screen → drop "semantic leakage screening" as a differentiator everywhere it appears; keep the statistical screen.
- *Effort:* 2 days. *Gates:* the leakage-screening claims in WS-2/Doc 5; V1 is also graveyard case-test "garbage-in-confidence-out".

**V2 — Components-as-features lift (the composition bet, cheapest honest version).**
- *Hypothesis:* features extracted by structural models (HMM states, cluster IDs, latent factors) lift a GBT beyond raw features — on data designed to contain such structure, and measurably on realistic data.
- *Method:* three planted-structure datasets (HMM-regime labels driving the target; cluster-heterogeneous coefficient signs; latent-factor interactions) + one realistic association-shaped synthetic (or a real dataset if available). Arms per dataset: GBT-on-raw vs GBT-plus-extracted (hand-wired scripts: hmmlearn → state per row; kmeans → cluster id; implicit-ALS → embedding). All arms same locked holdout via the referee.
- *Measured:* holdout AUC/R² delta per dataset; extraction cost in seconds.
- *PASS:* ≥+0.03 AUC on ≥2 of 3 planted datasets AND ≥+0.01 on the realistic one. *REVISE:* lift on planted only → composition machinery demoted to "when structure is known present" (triage must cite structure evidence before composing). *KILL:* no lift even on planted-to-favor-it data → **Docs 4–5 composition machinery demoted to research track; plan proceeds pillars-only.** This is the big one — it is exactly Arie's challenge, made falsifiable.
- *Effort:* 3 days. *Gates:* Doc 4 composite executor, hybrid search, the "Cambrian explosion" framing.

**V3 — Task coverage beats task-shoehorning (the "GBT can't ask these questions" bet).**
- *Hypothesis:* on censored time-to-lapse data, a survival model materially beats the GBT workaround (fixed-window binary classification) on decision-relevant metrics.
- *Method:* planted-hazard survival data, censoring 20–50%. Arms: CoxPH/AFT (lifelines, direct) vs GBT binary at 30/60/90-day windows. Measured: C-index vs window-AUC; calibration of "who lapses within X days"; the *timing* decision quality (rank correlation of predicted vs true lapse order among the censored).
- *PASS:* survival arm wins timing + calibration clearly (this is near-certain statistically — the experiment exists to produce the DEMONSTRATION ARTIFACT for the team, not to resolve doubt). *KILL:* n/a realistically; if GBT-windows ties, the survival family gets deprioritized in the demand queue.
- *Effort:* 1–2 days. *Gates:* the T4/T5/T7 "business-question set" prioritization; the pitch's task-coverage argument.

**V4 — Agent triage validity (the grand-plan loop bet, pre-build).**
- *Hypothesis:* an LLM given ONLY computed statistics (no framework) makes the correct commit/defer/combine/task-family call at ≥80%.
- *Method:* the 12 golden scenarios from Doc 5, generated by the mini-generators, but run RAW: compute the qualia stats (VIF, skew, censoring, Hopkins, seasonality strength, sparsity, class balance, n/p) into a JSON block → prompt the LLM for a structured verdict + cited statistics → score against planted truth. 3 repetitions per scenario across seeds; also an ablation arm WITHOUT the stats (schema only) to prove the stats matter.
- *Measured:* decision accuracy; citation validity (does the cited stat actually support the verdict — human-check 20 samples); stats-vs-no-stats delta.
- *PASS:* ≥80% accuracy with stats AND ≥15-point delta over no-stats. *REVISE:* 60–80% → triage ships as "advisory with human confirm" not autonomous. *KILL:* ≤ chance or no stats-delta → Doc 5's Architecture Strategist redesign required before build.
- *Effort:* 2 days. *Gates:* Doc 5 triage design; the Statistician sub-agent's value claim.

**V5 — The p-hacking reproduction + containment (Arie's case test; the honesty bet).**
- *Hypothesis:* (a) an agent iterating freely against a visible validation set overfits it substantially (reproducing the AutoML leaderboard failure), and (b) the mechanical locked holdout fully contains the damage.
- *Method:* pure-noise dataset + weak-signal dataset. Arm A: agent gets 20 iterations to "improve" features/hyperparameters seeing validation scores each time (no holdout). Arm B: same, but final judgment on the referee's locked holdout. Measured: validation-vs-holdout optimism gap in Arm A (expect large on noise); Arm B's holdout verdict (expect: noise → dummy-level, honestly).
- *PASS:* Arm A shows ≥0.1 AUC optimism on noise (failure reproduced) AND Arm B's holdout stays at dummy level (containment proven). *KILL:* n/a — either outcome is informative; if the agent does NOT overfit validation, that's publishable news and still fine.
- *Effort:* 1–2 days. *Gates:* nothing to gate — this one exists to be SHOWN (to Arie specifically): the graveyard's deadliest failure, reproduced and mechanically contained.

**V6 — Calibration deficit on shipped models (the WS-1 quantification).**
- *Hypothesis:* the shipped PS models' raw scores are materially miscalibrated and simple isotonic post-hoc fixes them.
- *Method:* planted-probability data through the LIVE shipped sidecar (xgboost + logistic); measure ECE/Brier raw vs with a 20-line isotonic script on a calibration split.
- *PASS:* raw GBT ECE ≥0.05 and isotonic cuts it ≥50% (near-certain; produces the number that justifies WS-1 in one sentence). *Effort:* 1 day. *Gates:* none — ammunition.

**V7 — Aggregation leakage reproduction (the Featuretools grave; the as-of bet).**
- *Hypothesis:* naive relational aggregates (no time cutoff) inflate validation and collapse on temporally-honest evaluation; as-of aggregates don't.
- *Method:* planted event-log data where post-decision events correlate with the label. Arms: aggregates computed over ALL history vs as-of the decision date. Both → GBT → referee.
- *PASS:* naive arm shows large validation-vs-temporal-holdout gap; as-of arm shows none. *Effort:* 1 day. *Gates:* the Sonar-aggregates work item's design (A30/B8); graveyard case-test #2 for the Arie memo.

**V9 — Monitoring / drift detection (Arie's #1 priority; the biggest Phase-0 gap).**
- *Hypothesis:* a PSI/KS drift monitor on a scored population flags a distribution shift BEFORE holdout performance visibly rots, and the challenger-vs-incumbent comparison fires correctly.
- *Method:* train a model on a baseline period; score a later population into which a planted covariate shift is injected (dial-controlled). Track PSI/KS on features + score vs the training snapshot, and true holdout AUC over the shifted periods. Show the monitor's alarm precedes the AUC decay; then train a challenger on fresh data and show the direction-aware comparison recommends promote/hold correctly (never auto-promotes).
- *PASS:* PSI crosses its 0.25 "stale" threshold at or before the period where holdout AUC drops materially; challenger comparison direction-correct. *REVISE:* monitor lags the decay → thresholds retuned. *KILL:* n/a — monitoring ships regardless (it's a pillar), this sizes it.
- *Effort:* 1 day. *Gates:* nothing hard — closes the stated-priority gap and produces the monitoring artifact for Arie.

**V10 — Uplift / persuadables (the flagship business claim; untested + finicky).**
- *Hypothesis:* on planted treatment-effect data, a T-learner recovers the four segments (persuadable / sure-thing / lost-cause / sleeping-dog), and uplift-targeting beats risk-targeting on realized net outcome — including NOT contacting the sleeping-dogs.
- *Method:* generate members with a planted baseline conversion AND a planted treatment effect that varies by segment (some positive, some ~zero, some NEGATIVE = sleeping-dogs). Two calibrated base classifiers (T-learner) → uplift = P(y|treat) − P(y|control). Compare three targeting policies on a held-out set by realized net conversions: (a) contact everyone, (b) contact highest-risk, (c) contact highest-uplift. Recover the segment assignments vs planted truth (Qini/uplift-at-k).
- *PASS:* uplift-targeting's net outcome beats risk-targeting by a clear margin AND correctly declines to contact the planted sleeping-dogs; segments recovered above chance. *REVISE:* uplift ranks but segment recovery weak → claim narrowed to ranking. *KILL:* uplift no better than risk-targeting on planted causal data → drop the persuadables framing.
- *Effort:* 1–2 days. *Gates:* the uplift components + the headline "who is worth contacting" business claim. Depends on calibration (V6, PASS).

**V8 — Story-tag retrieval (the reuse bet; weakest, cheapest, optional).**
- *Hypothesis:* meaning-tagged components are found for new tasks better than keyword search over technical names.
- *Method:* 30 hand-written component descriptions (technical + nominal), 15 task queries with known-correct answers; arms: keyword-over-technical vs embedding-over-nominal-tags vs both.
- *PASS:* nominal-tag arm top-3 accuracy ≥0.8 and ≥0.2 over keyword. *REVISE/KILL:* reuse-before-rebuild stays but the tagging investment gets right-sized. *Effort:* 1 day. *Gates:* Doc 5 story-layer sizing.

# ADDENDUM 6 — Real-Data Validation on More Cheese Demo V2: TWO SEPARATE TRACKS (Infra ⟂ Theory)

**Provenance / trigger (2026-07-15, user).** Phase 0 (Addendum 5) validated the plan's bets on *synthetic planted-truth* data. The committed next gate was "rerun the composition bets on ONE real association dataset." That gate is now widened by two user directives: **(1) validate the FULL plan on real data — every pillar and the whole generative chain, not only the Arie-contested subset; (2) the centerpiece is *how a model reasons through different situations* — and the chain it drives: reason → compose high-grade models on the component basis → form stories → reuse components → produce different model classes.** And one governing methodology directive that reshapes everything below.

**THE GOVERNING PRINCIPLE (new, binding): test the INFRASTRUCTURE and the THEORY separately.** The two questions this plan must answer are orthogonal and must never be entangled in one experiment:
- **THEORY** — *"are the modeling ideas sound?"* (agent reasoning-through-situations, component composition producing high-grade models, task coverage, calibration, monitoring, leakage discipline, story formation).
- **INFRA** — *"does the MCF machinery execute correctly?"* (the migration/entities/catalog, `validateCompositeSpec`, `FeatureAssemblyExecutor`, the sidecar, the composite executor, RSP binding).

**Why separate (the user's "it is easier"): attribution.** A combined real-data end-to-end test that goes red is *unattributable* — you cannot tell a wrong idea from broken plumbing. Proven apart, each red is attributable by construction: a Theory red means the idea needs revision; an Infra red means a bug. They meet at exactly ONE integration point (A6.3), and because both halves are pre-proven, a failure THERE is definitively an integration defect. This also maps onto the earlier work-split-by-language-seam ask: Theory is Python-stats + agent-reasoning flavored; Infra is the MJ TS/metadata/sidecar pipeline. It is a hardening of the existing Tier-0/Tier-1 boundary (A5.4) specifically for the real-data phase: **the idea-proof is never routed through the infra, and the infra-proof never depends on real data or LLM judgment.**

**The dataset — More Cheese Demo V2** (`BlueCypress/morecheesev2`, `dev` branch, `SQL Scripts/morecheese-bulk/*.sql`; ~16k records across a real association schema). Loaded standalone (no DB) via `phase0/realdata/load_morecheese.py` — a T-SQL `VALUES` parser → pandas (all multi-batch INSERTs captured). Tables: `Person` (385 members: Segment, Region, JoinDate, Org), `MembershipPeriod` (1,558: Start/End/RenewalDate, **Status** ∈ Renewed 1173 / Active 305 [censored] / Lapsed 69 / PendingRenewal 11, CancellationDate/Reason, DuesAmount, Tier, AutoRenew), `EventRegistration` (3,337: RegisteredOn, Attended), `CourseEnrollment` (894: Status, CompletedOn), `Order`/`OrderLine`/`Payment` (~3.3k each). **Why it's the right substrate:** (a) it poses *genuinely different* modeling situations from one schema — renewal classification, censored time-to-lapse (305 live Actives), dues/attendance forecasting (2013→2026 spine), engagement segmentation, CLV; (b) it carries *real leakage traps* (`CancellationDate`, `CancellationReason='non-payment — lapsed'`, `RenewalDate`, `Status`) — the honesty pillar can be proven on real post-outcome columns, not planted ones; (c) it is realistic-but-synthetic demo data, so it tests *messy multi-table assembly + does-composition-lift-when-not-planted-to-favor-it*, while staying honest that it is not observational field data.
