System Map — how it all fits together

The whole platform in two pictures: what contains what (the hierarchy) and how work flows (the lifecycle). Red = the open seams — the hierarchy questions that are still undecided. Purple = actors, which live in no container and operate on everything.

1 · Containment — what lives inside what

Workspaceone per environment — everything a signed-in user sees
Projectsthe organizing container ("Folders" today) — nestable, color + icon
Nesting semantics (roll-up, inheritance, move rules) undecided — but nested trees ARE shipped
Conversationa chat with agents · has a pinned default agent, mode, plan preference
Messages — flat avatar rows; user turns, agent turns, form pills, command chips
Agent runs — one per agent turn: steps, tokens, cost (the "invoice")
Attachments — files/images on messages
Artifacts (origin) — versioned deliverables born here, shown as cards
Voice sessions — a live call inside this conversation; channels (whiteboard · media · remote browser); collapses to a timeline card
Threads — replies-to-a-message side panel (entry orphaned today)
Project memory — notes agents keep for THIS project (P1.6; keep/edit/forget)
Task graphs — Sage's multi-step workflows; Task.ProjectID exists but is never stamped — they currently land in no container
Ungroupedconversations in no project
Temporary chatsoutside everything — read and write no memory, join no project (D20)
Collectionsa SECOND tree: curated libraries of saved artifacts, nestable, shareable — relationship to Projects undecided (likely: project = where an artifact is born, collection = where it's curated)
Global memoryorg-wide notes every agent reads everywhere
Agentsactors, not containers
Sage — generalist; delegates, runs task graphs
Skip — remote analytics specialist; runs its own loop (plan/skills delegated)
Skills — capability bundles an agent may activate
Plan mode — "show me the plan before you act" gate on a run
Routinespersonal schedules — deliberately outside Projects (v1)
Each run = an agent run on a timer → notification + a linked conversation
Tasks viewworkspace-wide window onto all task graphs (Gantt, dependencies)

2 · Flow — how work moves through the system

F1 You message→Agent run→Reply The core loop. The run reads memory (global + project) on the way in; plan mode can insert an approval gate before it acts.
F2 Agent run→Artifact v1→v2, v3…→Saved to Collection Deliverables: born in the conversation, versioned by agent and human edits, optionally curated into collections. Remix forks one into a new conversation.
F3 Agent run→Task graph→Sub-runs→Outputs back to chat Multi-step work: Sage builds a dependency graph, sub-tasks execute, results land as messages/artifacts. Should be stamped with the project (OPEN — currently isn't).
F4 Conversation→"Remembered" moment→Provisional note→Kept → read by every future run in scope Memory: written where it's learned (keep/edit/undo at capture), scoped project or global, then flows into F1 forever. Temporary chats skip this entirely.
F5 Phone button→Live voice session→Channels + delegations→Timeline card in chat Voice is a modality of the same conversation, not a separate place — delegated work becomes agent runs (F1), and the session collapses to a reviewable card.
F6 Routine (schedule)→Agent run→Notification + linked conversation Same F1 loop, fired by a clock instead of a person. Personal, project-agnostic in v1.
F7 Share→Conversation · Artifact · Collection today→Project as THE boundary (planned) Sharing exists per-thing today; the Projects vision makes the project the sharing boundary (members, roles) — which is why the hub has a Members tab.

Red = the open seams — nesting semantics, task→project stamping, collections↔projects. These are the hierarchy decisions; everything else above is settled structure. Purple = actors — agents and schedules act ON the containers, they don't live in them. Companions: placement-board.html (every feature, statuses) · BASELINE-INVENTORY.md (the raw record).
