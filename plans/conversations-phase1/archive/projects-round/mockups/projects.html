Projects — from "Folders" to the first-class workspace container

The sidebar's "Folders" are already MJ: Projects underneath. These three directions rename the concept to Projects and give it a real presentation: conversations, agent memory (P1.6), Sage's task-graph workflows, artifacts, and sharing — scoped to the project. Three divergent philosophies below, all in the ng-conversations design language (navy sidebar, MJ tokens, existing chrome). Toggle your OS theme to preview dark mode.

Option A

Project Hub — a project is a place you open

Clicking a project opens a landing page — overview, memory, workflows, artifacts, members — one destination that answers "where is this initiative?" before you ever open a chat. Metaphor: a Notion/Linear project page, powered by agents.

Option B

Project as Workspace — a context you work inside

A slim project rail on the far left switches the entire workspace lens: the sidebar becomes the active project — its conversations, workflows, artifacts, and memory in one column — and everything you do happens inside that project until you switch. Metaphor: Slack workspaces / Discord servers, for initiatives.

Option C

Companion Canvas — the project rides alongside the chat

Nothing about today's layout changes: the sidebar keeps the Projects tree and the chat stays the hero. But every conversation inside a project gains a live companion panel — memory, the running workflow, artifacts, sibling chats — always in reach, never in the way. Memory moments surface inline as they're learned. Metaphor: Claude Projects' knowledge panel, grown up.

Temporary chats have no companion — no project, no memory.
Why it works: zero disruption — today's tree, today's chat, no new navigation level. Project context is ambient: memory is visible and editable where it's learned (the inline "Remembered" moment doubles as P1.6's provisional-note review), the workflow the agent kicked off is watchable without leaving the thread, and artifacts land where you're looking. Cheapest to ship: the panel is a slot beside the existing artifact panel. Tradeoff: the project never gets a face of its own — no overview/landing to share or link; panel + artifact viewer compete for the right edge on smaller screens; project-level management (rename, members, bulk moves) still needs a home elsewhere.
