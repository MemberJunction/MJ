# MemberJunction Docs Site — Plan & Decision Record

> **Status:** Implemented (Phase 1). The site lives in **[`docs-site/`](../../docs-site/)** in this repo and deploys via [`.github/workflows/docs.yml`](../../.github/workflows/docs.yml).
> **Remaining:** legacy-content audit, CNAME flip to `docs.memberjunction.org`, legacy sunset (see [Phases](#5-phases) below).
> The static HTML prototype that previously lived beside this plan was throwaway and has been deleted now that the real build exists.

---

## 1. Goals (unchanged)

1. **Single source of truth.** All long-form prose lives in the repo it documents (READMEs, `/guides/`, JSDoc). The site never owns content — it renders content from the repo at build time.
2. **Preserve the brand URL.** `docs.memberjunction.org` continues to resolve to a useful, branded landing page.
3. **100% automation.** No manual sync step, ever. Guides, package READMEs, and the TypeDoc API reference are woven in at build time.
4. **Cheap to run.** Free GitHub Pages hosting; steady-state maintenance measured in minutes per month.
5. **Clear path for newcomers.** "Where do I start?" is answered in one click from the landing page.

Non-goals also unchanged: not a CMS, not versioned, not a forum, and **never** a hand-curated copy of READMEs.

## 2. Decisions

| Question | Decision | Rationale |
|---|---|---|
| **SSG** | **Astro Starlight** | Confirmed by Craig 2026-07-23 (Docusaurus was considered — familiar from React work — but Starlight's markdown-first model, built-in Pagefind search, and lighter build won for a site that mostly renders existing `.md`). |
| **Where the site lives** | **In this repo, `docs-site/`** — *reverses the original separate-repo recommendation* | The TypeDoc pipeline (`docs.yml`) already lives here and owns the repo's Pages slot; ~330 of the site's pages source from files in this repo, so an in-repo build needs **no fetch pipeline, no dispatch PATs, no nightly staleness rebuilds**. `docs-site/` sits outside the npm workspaces so the monorepo build is untouched. Ecosystem repos (public) are still fetched at build time. |
| **TypeDoc** | Reuse the existing `docs.yml` TypeDoc build; site ships it under **`/api/`** | Already automated on every release; the site's 404 transparently redirects old root-level TypeDoc deep links into `/api/`. |
| **CLAUDE.md content** | **Not surfaced.** Agent **skills** get a first-class catalog instead | Per review: skills (`.claude/skills/*/SKILL.md`, auto-discovered) are useful to developers *using* MJ; CLAUDE.md is an internal contributor handbook. |
| **MJC** | CTA on the hero, sidebar badge link, Getting Started callout, Community section | Per review: shameless plug for [MJ Central](https://central.memberjunction.com) throughout. |
| **Repos with their own docs** | `extraLinks` per ecosystem source → "For more info →" links (e.g. Forge Wiki) | Per review. Add entries in `docs-site/scripts/lib/ecosystem.mjs`. |

## 3. How the automation works

`docs-site/` is an Astro Starlight app whose content is generated by [`scripts/ingest.mjs`](../../docs-site/scripts/ingest.mjs) on every build:

| Content | Source | Discovery |
|---|---|---|
| Developer guides (~40) | `guides/*.md` | Automatic — new guide file ⇒ new page |
| Package pages (~280) | `packages/**/README.md` at package roots + grouping dirs | Automatic — new package README ⇒ new page; directory index built from `package.json` metadata |
| Overview / Deployment / Upgrade / Contributing / Metadata | root repo docs | Fixed list |
| Agent skills catalog | `.claude/skills/*/SKILL.md` frontmatter | Automatic |
| Ecosystem cards | GitHub API (Skyway, Forge, VSCode, bizapps-common) | Build-time fetch, fail-soft |
| `/api/` | TypeDoc over all packages | Built in `docs.yml`, copied into `dist/api/` |

**Link rewriting** (the load-bearing detail, implemented in [`scripts/lib/rewrite.mjs`](../../docs-site/scripts/lib/rewrite.mjs), unit-tested): every relative link in ingested markdown is resolved on the MDAST — targets also rendered on the site become **relative site links** (deploy-base-agnostic); repo files not rendered (source code, CLAUDE.md, SQL) become **GitHub blob/tree URLs pinned to the build's commit SHA**; relative images become pinned raw URLs; unresolvable links are left unchanged with a build warning.

**Deploy** (`docs.yml`): monorepo build → TypeDoc → docs-site tests → ingest + Astro build (`DOCS_BASE=/MJ`) → TypeDoc copied to `/api/` → GitHub Pages. Triggers: after each npm publish from `main` (as before), on docs-content pushes to `main`, and manually. PRs touching docs content get a fast build gate via [`docs-site-ci.yml`](../../.github/workflows/docs-site-ci.yml) (no monorepo build, no TypeDoc).

## 4. Maintenance model

| Action | Where it happens | What you do on the site |
|---|---|---|
| Edit / add a guide | PR into `guides/` | Nothing — auto-appears |
| Add a package | PR into `packages/` (with README) | Nothing — auto-appears |
| Edit landing/architecture/community connective copy | `docs-site/src/content/docs/*.mdx` | Normal PR |
| Add an ecosystem repo or its docs link | `ECOSYSTEM_SOURCES` in `docs-site/scripts/lib/ecosystem.mjs` | One-line PR |
| API reference refresh | Automatic on release | Nothing |

## 5. Phases

- **Phase 0 — Legacy audit (open).** `docs.memberjunction.org` is on readme.com and largely stale. Export the project, skim for any content *not* already in-repo (expected: a handful), move-or-discard, and capture the top legacy URLs for redirects. Do not invest in a full port.
- **Phase 1 — Build (done).** This implementation. Deploys to `https://memberjunction.github.io/MJ/`.
- **Phase 2 — Soft launch (open).** Team review of the deployed site; fix missing content and search quality; add redirect stubs for the top legacy URLs.
- **Phase 3 — CNAME flip (open).** Add `docs-site/public/CNAME` (`docs.memberjunction.org`), set the custom domain in the repo's Pages settings, drop DNS TTL, switch the `docs` CNAME to `memberjunction.github.io`, wait for cert, QA, restore TTL. Then set `DOCS_BASE=/` and `DOCS_SITE=https://docs.memberjunction.org` in `docs.yml` — content needs no changes (all internal links are relative). Old `memberjunction.github.io/MJ/` links keep working via GitHub Pages' domain redirect.
- **Phase 4 — Sunset (open).** After ≥30 days: confirm zero legacy traffic, cancel the readme.com subscription, archive the export privately.
