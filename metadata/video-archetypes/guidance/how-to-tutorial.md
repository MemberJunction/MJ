# How-To Tutorial Guidance

## Purpose
Use the How-To Tutorial archetype for 60 to 180 second instructional walkthroughs that teach viewers how to complete a concrete workflow step by step. Pacing is deliberate and structured around numbered state transitions so viewers can follow along without pausing repeatedly.

## Beat Intent
- **hook**: Show the finished result in the first three seconds so the viewer knows exactly what they will be able to build or accomplish.
- **prerequisites**: Briefly list the starting screen, inputs, or permissions required before beginning step one.
- **step-one**: Demonstrate the initial action with a clear focal highlight around the active field or command.
- **step-two**: Advance to the configuration or transformation step, holding on the resulting state long enough for verification.
- **verification**: Show how to confirm that the workflow succeeded using the real output state.
- **close**: Recap the three-step sequence on a clean checklist card and point to the next logical workflow.

## What to Avoid
- Never jump between screens without showing the trigger control or navigation path that connects them.
- Avoid fast camera pans across dense interfaces; use smooth, localized zoom-and-hold on the active region.
- Do not paraphrase button labels or command flags; on-screen callouts must match the exact UI strings.

## Facts Rule
Never invent product screens, menu names, CLI flags, metrics, logos, or people. Every screen state in a tutorial must come from supplied or captured screenshots in `Assets.Approved` or faithfully reflect verified code/data inputs. If required screenshots or steps are missing, ask the caller before proceeding.
