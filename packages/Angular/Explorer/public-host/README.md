# @memberjunction/ng-public-host

Public pages for MJ Explorer: pages that a visitor can open before signing in, such as a product landing page or a pricing page. Open Apps ship them; the public host renders them at `/p/<slug>`.

A public page does not start Explorer, the auth SDK, GraphQL or metadata. Explorer's start-up starts the public host instead, and the host loads only Angular, this package and the page's own chunk.

## How it starts

The host app's `main.ts` only calls `StartExplorer()` from `@memberjunction/ng-explorer-app/bootstrap`:

```ts
import { StartExplorer } from '@memberjunction/ng-explorer-app/bootstrap';
import { environment } from './environments/environment';
import { PUBLIC_PAGES } from './app/generated/public-pages.generated';

StartExplorer({
  Environment: environment,
  PublicPages: PUBLIC_PAGES,
  LoadAppModule: () => import('./app/app.module').then((m) => m.AppModule),
});
```

- A path under `/p/` starts the public host. The host finds the page for the slug, loads its chunk and renders it.
- Every other path starts Explorer as before.
- `main.ts` holds no start-up logic, so a start-up change reaches a host with a package update.

`PUBLIC_PAGES` is generated by `mj codegen manifest --open-app-client-bootstrap` (the host's `prestart` and `prebuild` scripts) from the `publicPages` entries that `mj app install` writes into `mj.config.cjs`.

## Addresses, sub-paths and error pages

| Address | The page at that slug | Result |
|---|---|---|
| `/p/pricing` | any | The page |
| `/p/pricing/anything` | no `subPaths` | The error page. The page's code is not downloaded |
| `/p/docs/guides/setup` | `"subPaths": true` | The page, which reads `Context.SubPath` |
| `/p/docs/guides/missing` | `"subPaths": true`, and the page calls `Context.ShowNotFound()` | The error page |
| `/p/no-such-slug` | none | The error page |
| `/p/Pricing` | any | The browser goes to `/p/pricing` |

An Open App can ship error pages. The host uses the error page of the requested folder, then of each parent folder, then of the root. When no installed app has one, or it does not load, the host shows its own.

```json
"publicPages": [
  { "slug": "docs", "package": "@acme/pages", "export": "DocsPage", "subPaths": true },
  { "role": "error", "scope": "docs", "package": "@acme/pages", "export": "DocsNotFoundPage" },
  { "role": "error", "scope": "", "package": "@acme/pages", "export": "NotFoundPage" }
]
```

- A `scope` is a folder under `/p/` that starts with a slug of the same app, or `""` for all of `/p/`.
- When two installed apps have a root error page, the host uses the first one in `publicPages` of `mj.config.cjs`.
- An error page is a public page component. It reads `Context.Error()`: the reason (`not-found` or `load-failed`) and the requested path.
- Show the requested path as text only. Never use it as a link or as markup: whoever made the link wrote it.
- The host sets `<meta name="robots" content="noindex">` whenever an error page shows. The response status is 200 on most web hosts.

## Page file: title, link preview and security policy

Link previews (in chat apps and social sites) and search engines read a page's HTML. They do not run its JavaScript. So MJ Explorer's build writes one HTML file for each page: `public-pages/<slug>.html`. Each file is a copy of Explorer's `index.html` with:

- `<title>` set to the page's `title` from `mj-app.json`
- `<meta name="description">` and the `og:title`, `og:description`, `og:type` and `twitter:card` tags, from the page's `title` and `description`
- `<meta name="robots" content="index, follow">` (Explorer's own `index.html` has `noindex`)
- a Content Security Policy: `script-src 'self'` plus the hashes of the file's inline scripts, `object-src 'none'` and `base-uri 'self'`
- no map library tags, and a plain link for the main stylesheet (the policy blocks the inline handler that Angular's build uses)

`mj explorer postbuild --dir dist/MJExplorer/browser` (the host's `postbuild` script) writes these files after `ng build`. It reads the pages from `publicPages` in `mj.config.cjs`. An error page gets no file.

A public page shares its browser origin with Explorer, and Explorer keeps sign-in tokens in the browser's storage. The policy is what stops a script from another site from reading them. So:

- A public page loads no script from another site: no tag manager, analytics script or chat widget.
- A public page never shows a password field. Sign-in goes through `Context.StartSignIn()` only.
- Never register an address under `/p/` as a redirect address in an identity provider.

## Web host rules

The web host serves `public-pages/<slug>.html` for `/p/<slug>` and for every address under it. Every other `/p/` address gets `index.html`, as every Explorer address does.

Azure Static Web Apps: `mj explorer postbuild` adds the rules for each page to the `staticwebapp.config.json` in the build folder:

```json
"routes": [
  { "route": "/p/pricing", "rewrite": "/public-pages/pricing.html" },
  { "route": "/p/pricing/*", "rewrite": "/public-pages/pricing.html" }
]
```

nginx (as in `docker/regression/nginx.conf`):

```nginx
location ~ ^/p/([a-z0-9-]+)(/|$) {
    try_files /public-pages/$1.html /index.html;
}
```

- Without a rule, `index.html` answers. The page shows, but its HTML has Explorer's title, no link preview, no Content Security Policy and `noindex`. Add the rule before a page is announced to the public.
- Explorer's service worker does not answer `/p/` addresses, so the web host receives them also from a visitor who used Explorer before.
- In development, `pnpm start` serves `index.html` for `/p/` addresses.

## Writing a public page

A public page is a standalone component that extends `BasePublicPage`:

```ts
import { Component } from '@angular/core';
import { BasePublicPage } from '@memberjunction/ng-public-host';

@Component({
  selector: 'acme-pricing-page',
  template: `
    <h1>Pricing</h1>
    <button type="button" (click)="Context.StartSignIn()">Sign in</button>
  `,
})
export class PricingPageComponent extends BasePublicPage {}
```

`Context` (a `PublicPageContext`) gives the page:

| Member | What it is |
|---|---|
| `Slug`, `SubPath`, `QueryParams` | The parts of the URL after `/p/`. `SubPath` is empty unless the page has `subPaths` |
| `ShowNotFound()` | Shows the error page in place of this page, for a sub-path that is not one of its views |
| `Error()` | On an error page: the reason and the requested path |
| `Brand()` | The sign-in page design from Login Studio (logos, theme), or `null` |
| `BuildMJAPIURL(path)` | An absolute URL for the Open App's `pre-auth` server endpoints |
| `StartSignIn()` | Opens Explorer's sign-in screen. A new visitor signs up there when the identity provider allows it |

Rules for a public page:

- Never pass `SubPath` or `QueryParams` to `innerHTML`, `bypassSecurityTrust*`, a link target or `window.location`.
- Get data only from the Open App's `pre-auth` server endpoints. There is no session and no GraphQL client.
- Export the page from a package entry that does not import the app's Explorer code, so the page chunk stays small.
- Use MJ design tokens for colours. The host runs without zone-based change detection, so use signals for state.
- The page runs in Explorer's `index.html`, so Explorer's global styles and Font Awesome are loaded. Put styles that only the page needs in its component.
- Give the page a `title` and `description` in `mj-app.json`. The build writes them into the page's HTML (see [Page file](#page-file-title-link-preview-and-security-policy)). To change the title while the page runs, use `inject(Title)`.

Declare the page in the Open App's `mj-app.json`:

```json
"publicPages": [
  {
    "slug": "pricing", "package": "@acme/app-public", "export": "PricingPageComponent",
    "title": "Pricing", "description": "Plans for every team."
  }
]
```
