## Findings

| Issue | Severity | Disposition |
|---|---|---|
| IT52 Unified Search Seams — lexical search SQL builds string-vs-uniqueidentifier predicates | recorded — **does not block** (Craig, 2026-08-07) | The 5.51.0 unified-search seam interpolates scope values into UUID-typed filter columns unvalidated (server error: `Conversion failed when converting from a character string to uniqueidentifier`; observed with fixture scope `AgentID = 'mj-it-benign-zzz-000'`); the resolver errors and the client sees null. Reproduced identically on plain and FTS-enabled SQL — not environmental. Mitigation context: Explorer's user-facing search at 5.51.0 predates this seam, and the Izzy stage soak reported search working; the seam was rebuilt on next by the pluggable-search work (#3378), so the forward fix likely exists. Ruling: recorded — user-facing search at 5.51.0 predates the seam and works in stage; the seam is new machinery, rebuilt forward on next (#3378). |
| Shipped demo metadata pack references pre-v5 unprefixed entity names | recorded — does not block | The install payload's `SQL Scripts/demo/metadata/*/.mj-sync.json` references entities `Queries` and `Query Categories`; on a 5.51.0 install those exist only as `MJ: Queries`/`MJ: Query Categories` (v5.0 prefix), so the demo pack cannot apply (validation: "Entity not found in metadata"). Core install unaffected. Fix forward: re-prefix the demo pack. |
| RunSingleFilter fail-closed fix (#3525 → backported #3539) | recorded | Latent on 5.x (no shipped ActionFilter rows); banked on `lts/5` for 5.51.1. Does not block. |
| Agent memory enabled by default crashed an agent in Skip stage | recorded — mitigated; blocking ruling pending cert owner | Surfaced in the Skip stage soak (Caeleb, 2026-08-13): with agent memory on by default, an agent crashed with "seemingly some other issues" alongside. Disabling agent memory cleared it. Forward fix cited by Caeleb: [#3777](https://github.com/MemberJunction/MJ/pull/3777) (open on next — "stop cross-server cache events poisoning entity_object engine caches"). Caeleb addendum (2026-08-13): the same issue also affects scheduled jobs on instances with Redis set up, as that is currently the only path that uses `OnExternalCacheChange()`. 5.51.x mitigation: disable agent memory. |
| SQL-injection exploits found during Skip-stage soak; fixes already on next (post-freeze) | recorded — **backport directed** (Craig, 2026-08-13) → 5.51.1 | Reported by Jordan (2026-08-13): "A couple of us did find some security exploits in MJ, specifically with SQL injection. The fixes are currently in next." Likely fix set (post-freeze merges; confirmation + lts/5 applicability analysis in progress): [#3428](https://github.com/MemberJunction/MJ/pull/3428) SQL parameterization + filter-value escaping hardening; [#3410](https://github.com/MemberJunction/MJ/pull/3410) SQL filter validation hardening (bundled with JWT + API-key-comparison hardening — may need splitting); further hardening still open in [#3633](https://github.com/MemberJunction/MJ/pull/3633). Cert owner ruling: security fixes are exactly what the LTS line backports — cherry-pick onto `lts/5` for 5.51.1, keeping fix commits isolated from feature changes. |
| Installer smoke-test readiness regex is stale — false "MJAPI failed to start" | recorded — does not block | The 5.51.0 installer's SmokeTestPhase waits on a readiness regex (`/Server ready at/i`) that matches nothing MJAPI prints at this tag, so it reports "MJAPI failed to start. Reason: Readiness timeout (120s) expired" — degraded to a warning while the install still reports overall success. Out-of-band verification on the same box: MJAPI bound port 4000 in 75s, printed `Ready http://localhost:4000/`, and served HTTP 401 to an unauthenticated GraphQL POST. Product boots fine; the installer's verdict is the defect. Fix forward: update the regex (and arguably fail closed rather than warn). Observed on the Windows gate-4 run; the regex is platform-independent. |
