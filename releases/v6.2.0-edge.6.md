# Field-level security close-out, alternate base views, and calendar events

## TL;DR
Field-level security close-out, Alternate Base Views, server-authored agent replies, native tool calling for the Loop agent, calendar events in Communication with a Calendar view type, and the content ingestion pipeline. Plus anonymous-guest isolation, `mj sync push` correctness, and CodeGen metadata-drift fixes.

**Upgrade Notes apply:** agent-reply API callers must switch to `userMessageId`, clients must upgrade with the server, and migrations apply on `mj migrate`.

Edge builds are prereleases.

MemberJunction 6.x is released under the [Business Source License 1.1](https://github.com/MemberJunction/MJ/blob/next/LICENSE); 5.x and earlier stay ISC. What the licence grants, and what needs certification, is in the [licence section of the v6 upgrade guide](https://github.com/MemberJunction/MJ/blob/next/UPGRADE-v6.0.md#license-change--read-this-first).

## New Features
- **Field-level security close-out** (`@memberjunction/core`, `@memberjunction/server`, `@memberjunction/graphql-dataprovider`, `@memberjunction/templates`, `@memberjunction/a2aserver`, and 35 other packages): A denied field value no longer reaches anyone the rule does not entitle: API callers, an LLM's context, message recipients, or stored artifacts such as embeddings, tags and logs. Entity objects never hold a value their user is denied on any load path, and work done on a user's behalf runs as that user: communication previews and sends, template renders, entity actions and A2A tasks. Caches that hold user-specific rows are keyed by user. `guides/FIELD_LEVEL_SECURITY_GUIDE.md` is rewritten with a developer checklist.
- **Alternate Base Views** (`@memberjunction/core`, `@memberjunction/core-entities`, `@memberjunction/generic-database-provider`, `@memberjunction/codegen-lib`, `@memberjunction/query-gen`, `@memberjunction/lists`, `@memberjunction/ng-entity-viewer`, and others): An entity can register governed SQL views (`MJ: Entity Alternate Base Views`) that keep full column parity with its `BaseView` while returning a curated row subset, such as active members or open orders. They work across RunView, CodeGen, caching, query generation, lists, data contexts, and Data Explorer.
- **Server-authored agent replies** (`@memberjunction/core-entities`, `@memberjunction/ai-agents`, `@memberjunction/server`, `@memberjunction/graphql-dataprovider`, `@memberjunction/ai-agent-client`, `@memberjunction/conversations-runtime`, `@memberjunction/ng-conversations`, and others): Only server code can create or change an agent's reply (`Role` `AI` or `Error`) in `MJ: Conversation Details`, so a client can no longer forge or rewrite what an agent said. The server creates the reply row itself from the user's message. See Upgrade Notes for the API change.
- **Native tool calling for the Loop agent** (`@memberjunction/ai-agents`, `@memberjunction/ai-prompts`, `@memberjunction/ai-anthropic`, `@memberjunction/ai-gemini`, `@memberjunction/ai-openai`, and others): The Loop agent can run as a provider-native tool loop. Retries and unanswered calls keep the call/result ordering Anthropic and OpenAI require, and Anthropic and Gemini reasoning blocks are carried across tool turns and dropped, not replayed, when the history before them changes.
- **Calendar events in Communication** (`@memberjunction/communication-types`, `@memberjunction/communication-engine`, `@memberjunction/communication-ms-graph`, `@memberjunction/communication-gmail`, `@memberjunction/ai-bridge-server`, `@memberjunction/telephony-adapters`): Providers can create, update, cancel, get and sync calendar events, each against an explicit calendar target. MS Graph and Gmail (Google Calendar) implement them. `CalendarEventLinks` ties events to any record through `MJ: Calendar Event Links` and syncs from `MJ: Calendar Sync States`. The realtime bridge's calendar sources now read through the providers.
- **Calendar view type** (`@memberjunction/ng-entity-viewer`, `@memberjunction/ng-ui-components`): Entity views can show records on a day, week or month layout by a start date field and an optional end date field.
- **Content ingestion pipeline** (`@memberjunction/content-pipeline`, `@memberjunction/content-pipeline-base`, `@memberjunction/record-set-processor`, `@memberjunction/content-autotagging`, `@memberjunction/core-entities`, and others): Discover, Extract, Tag, Segment, Embed and Delete stages run over Content Sources, Items and Chunks through Record Set Processing's new `Pipeline Stage` work type.
- **Bound action parameters for agent runs** (`@memberjunction/ai-core-plus`, `@memberjunction/ai-agents`, `@memberjunction/actions-base`, `@memberjunction/core-actions`): A run can fix action input parameters (`ExecuteAgentParams.boundActionParams`) that the model can neither see nor change. Bindings are stored on `MJ: AI Agent Runs` and reapplied when a run is resumed or continued.
- **Server-set query parameters and query approvals** (`@memberjunction/core`, `@memberjunction/query-processor`, `@memberjunction/core-entities`, `@memberjunction/server`, and others): Query parameters can be marked server-set so callers cannot override them, templates can use `Context` values (user, time), and `RequireApproved` runs only queries whose approved definition fingerprint still matches.
- **Properties on user views and dashboards** (`@memberjunction/core`, `@memberjunction/generic-database-provider`, `@memberjunction/ng-entity-viewer`, `@memberjunction/ng-dashboard-viewer`, `@memberjunction/ng-query-viewer`, `@memberjunction/ng-dashboards`): Saved views can declare typed inputs that each add a filter predicate, with server-only properties a caller cannot set. Dashboards gain properties, part input mappings, events and wires, and an Interactive Component part.
- **Executive Cockpit and event-driven agent wakes** (`@memberjunction/ng-dashboards`, `@memberjunction/ai-agents`, `@memberjunction/core-actions`, `@memberjunction/credentials`): A Chief of Staff cockpit in Explorer covers priorities, approvals of pending agent requests, agent wakes and the user's agent policy. A resolved agent request wakes its owner's agent on the next dispatcher sweep instead of waiting for the agent's schedule.
- **Record links, version history and form toolbar** (`@memberjunction/ng-base-forms`, `@memberjunction/ng-record-changes`, `@memberjunction/ng-entity-viewer`, `@memberjunction/ng-explorer-core`, and others): Forms show links in both directions (fields on the record and records that point to it) with hover previews, a record-changes drawer with in-form historical version previews, and a registry for custom toolbar buttons.
- **Per-connection integration catalog** (`@memberjunction/core-entities`, `@memberjunction/integration-engine`, `@memberjunction/integration-engine-base`): New `CompanyIntegrationObject` and `CompanyIntegrationObjectField` tables give each connection its own copy of its connector's objects and fields, so two connections to the same connector no longer overwrite each other's discovery. The engine reads them behind a per-connection flag.
- **Eleven Realtime models** (`@memberjunction/ai-elevenlabs`, `@memberjunction/ai-realtime-client`, `@memberjunction/realtime-runtime`, `@memberjunction/ng-conversations`): Adds ElevenLabs' `eleven_realtime_v1_mini` and `eleven_realtime_v1_max` as voice co-agent models on both server-bridged and browser-direct calls.
- **Local development sign-in** (`@memberjunction/auth-providers`, `@memberjunction/server`, `@memberjunction/ng-auth-services`, `@memberjunction/installer`): An `AuthProvider: "local"` option signs in with locally issued tokens for development. The server refuses to start with it in production, and its endpoints reject non-localhost requests.
- **Weekly AI model refresh** (`@memberjunction/ai`, `@memberjunction/aiengine`, `@memberjunction/core-entities`): Adds Kimi K3.1 Pro (routed through OpenRouter), Kimi K3.1 Pro Highspeed (inactive), and MiniMax-M3.1-Flash.

## Improvements
- **SQL dialect follows the database** (`@memberjunction/sql-dialect`, `@memberjunction/core`, `@memberjunction/ai-core-plus`, `@memberjunction/core-actions`, `@memberjunction/ai-agents`, `@memberjunction/server`): The SQL an agent prompt asks for, and the connection its result runs on, are chosen from the provider's platform, so agents on PostgreSQL no longer get SQL Server syntax.
- **Fewer read round trips** (`@memberjunction/core`, `@memberjunction/generic-database-provider`, `@memberjunction/integration-engine`, `@memberjunction/server`, and others): `RunViewParams.SkipTotalRowCount` skips the count query for callers that read only rows; a full `MaxRows: 1` read no longer runs a second `COUNT(*)`; RunView sends its view, count and aggregate queries in one batch.
- **Server scalability** (`@memberjunction/server`, `@memberjunction/core`, `@memberjunction/generic-database-provider`, `@memberjunction/api-keys`, and others): MJAPI replicas can be split into API and worker roles, with pluggable broadcast providers that keep caches in step across replicas.
- **Model failover respects its attempt limit** (`@memberjunction/ai-prompts`, `@memberjunction/ai-core-plus`): `FailoverMaxAttempts` now caps the requests a failover actually sends. Before, it was ignored and a failing prompt could walk every active model and vendor of its type.
- **OpenRouter model preference** (`@memberjunction/ai-openrouter`): `MJ_OPENROUTER_MODEL_PREFERENCE` sends an ordered fallback list that OpenRouter walks on errors.
- **Credential expiration enforced** (`@memberjunction/credentials`, `@memberjunction/ai-prompts`): `CredentialEngine` no longer hands out a credential past its `ExpiresAt`.
- **Duplicate detection** (`@memberjunction/ai-vector-dupe`, `@memberjunction/ai-vector-sync`, `@memberjunction/ai-vectors-memory`, `@memberjunction/ng-dashboards`, and others): A run records and uses the Entity Document it was started with, reports progress, finds duplicates past the first 1,000 records, and scopes vector queries to its document so several documents can share one index.
- **Integration discovery** (`@memberjunction/integration-engine`): Discovery stops at a memory budget instead of being killed, never saves an object with no fields, has a per-connection run deadline (default 12 hours), and its watchdog evicts entries for work that is no longer running.
- **DBAutoDoc key detection** (`@memberjunction/db-auto-doc`): LLM calls are time-bounded, keys are checked against the data before they are emitted, unique indexes count as primary-key evidence, seed context reaches the key passes, and organic keys are emitted hub-and-spoke instead of as all-pairs cliques.
- **Explorer forms** (`@memberjunction/ng-base-forms`, `@memberjunction/ng-shared`, `@memberjunction/ng-explorer-core`): A record shown in a custom form can be opened in the standard form, and an entity view can create a record directly in the standard form.
- **Brand theme on first paint** (`@memberjunction/ng-shared-generic`, `@memberjunction/ng-explorer-app`, and others): The org brand overlay survives a cold load, and `ThemeDefinition.IsDefault` lets a brand theme be the default without writing a user preference.
- **Chat overlay follows shell policy** (`@memberjunction/ng-explorer-core`, `@memberjunction/ng-explorer-app`): A shell chrome policy can turn the floating chat overlay off per user, as it already could for search and notifications.
- **Whiteboard and markdown** (`@memberjunction/ng-whiteboard`, `@memberjunction/ng-markdown`, `@memberjunction/ng-conversations`): Whiteboard items take an optional `Tag` and hosts can set the pen palette (hex colors only); markdown images can be height-capped and report clicks.

## Bug Fixes
- **Anonymous visitors isolated from each other** (`@memberjunction/server`, `@memberjunction/core`, `@memberjunction/livekit-room-server`, `@memberjunction/ai-agents`, and others): Every anonymous widget guest and magic-link invitee signs in as the one shared Anonymous user, so checks that compared only the user ID treated all of them as one person. A visitor who learned another's session ID could relay into, close or restore that realtime session. Sessions, conversation runs and LiveKit rooms now check a per-visitor identity.
- **Second user records on sign-in** (`@memberjunction/server`): A user added outside the sign-in flow (by an admin, an invite or a direct insert) got a duplicate `User` record on first login, because the cache refresh ran after auto-provisioning instead of before. Logins that match more than one record by email are no longer resolved by row order.
- **`mj sync push` migrations** (`@memberjunction/metadata-sync`, `@memberjunction/generic-database-provider`, `@memberjunction/core-entities-server`): Values from `@lookup` are written as natural-key subqueries instead of this database's IDs, so Metadata_Sync migrations update the right rows everywhere. Deletes run in dependency order, `--incremental` notices `@file:` changes, and Open App migrations call core procedures in the core schema.
- **CodeGen metadata drift** (`@memberjunction/codegen-lib`, `@memberjunction/schema-engine`, `@memberjunction/server`): CodeGen keeps `EntityField` rows in step with the views and procedures it regenerates, prunes orphaned fields, keeps IS-A children's inherited foreign keys, finds stale CRUD procedures, and fails the run when any step fails instead of reporting success. It no longer treats an entity's own primary key as its hierarchy parent.
- **PostgreSQL full-text search and idle connections** (`@memberjunction/codegen-lib`, `@memberjunction/postgresql-dataprovider`, `@memberjunction/server`): Enabling full-text search on a PostgreSQL entity creates its search objects instead of failing CodeGen, and a dropped idle pooled connection is logged instead of crashing MJAPI.
- **Recording status overwritten by session saves** (`@memberjunction/core-entities`, `@memberjunction/core-entities-server`, `@memberjunction/ai-agents`, `@memberjunction/server`): A stale save of an `MJ: AI Agent Sessions` record could clear a finished recording's status and mark it `Partial`. The recording-ledger columns are no longer updatable through an entity save.
- **Record Processes** (`@memberjunction/record-set-processor`, `@memberjunction/actions`, `@memberjunction/core`, `@memberjunction/global`): Pause and cancel work again (a checkpoint save overwrote the request), a record's run detail row no longer fails its foreign key to the action log, and runs of fast actions are no longer slowed by that wait.
- **Realtime calls** (`@memberjunction/realtime-runtime`, `@memberjunction/ai-realtime-client`, `@memberjunction/ng-conversations`, `@memberjunction/server`): A call that fails keeps its end reason and tells the user, a start that fails closes its session at once, a new call waits for the previous teardown, spoken openings are saved to the transcript, and late user transcripts keep their own start time.
- **Recording shard uploads** (`@memberjunction/realtime-runtime`): A network failure is retried instead of being logged as a server refusal, and a 4xx rejection is dropped.
- **Anthropic request shapes** (`@memberjunction/ai-anthropic`): Assistant prefill is withheld when thinking is on, and sampling parameters are not sent to models that reject them.
- **ElevenLabs tool results** (`@memberjunction/ai-realtime-client`, `@memberjunction/ai-elevenlabs`): Tool results are sent as the string ElevenLabs expects; sending an object closed the conversation.
- **Smart filters returning every row** (`@memberjunction/core-entities`): A Smart Filter whose generated WHERE clause is blank regenerates it instead of returning the whole table.
- **Record CRUD actions** (`@memberjunction/ai-engine-base`, `@memberjunction/aiengine`, `@memberjunction/ai-agents`, `@memberjunction/core-actions`): Get, Update and Delete Record accept every primary-key shape and fail fast on unknown fields.
- **Template and form saves** (`@memberjunction/ng-core-entity-forms`, `@memberjunction/ng-base-forms`, `@memberjunction/core`): A content-type change in the Template Editor is saved, and a later save or delete is no longer queued into an already-submitted transaction group and dropped.
- **Vector index external IDs** (`@memberjunction/core-entities-server`): A new Vector Index record that already has an `ExternalID` adopts that provider index instead of creating an empty one.
- **Open App installs** (`@memberjunction/open-app-engine`, `@memberjunction/dynamic-packages`, `@memberjunction/cli`): A missing GitHub credential for a private repository is reported as such instead of as a missing tag, packages can declare `platform` so Node-only packages stay out of the browser, and monorepo version tags are resolved from the tags that exist.
- **Flow editor runtime error** (`@memberjunction/ng-flow-editor`): `@foblex/flow` is pinned to 18.0.0, because 18.1.0 renamed exports and broke the flow editor at runtime with `NG0919`.

## Upgrade Notes
- **Agent replies are created by the server** (`@memberjunction/server`, `@memberjunction/graphql-dataprovider`, `@memberjunction/ai-agent-client`, `@memberjunction/conversations-runtime`, `@memberjunction/ai-agents`, `@memberjunction/task-graph`): `RunAIAgentFromConversationDetail` takes `userMessageId` (the user's saved message) instead of `conversationDetailId` (a reply row the caller created). The server creates the reply row and names it in the acknowledgement. Client code that creates or edits `AI`/`Error` rows in `MJ: Conversation Details` is refused. `AgentClientSession.RunAgentFromConversationDetail` takes `UserMessageId`, and `TaskContinuationParams.SubmittedByUserID` is required.
- **Upgrade clients with the server** (`@memberjunction/graphql-dataprovider`, `@memberjunction/server`): Older `@memberjunction/graphql-dataprovider` builds send denied fields at their defaults when a transaction group creates a record, and this server refuses that input for a restricted user. Reload open browser tabs, and move pinned consumers to the matching client release.
- **Template renders need their user** (`@memberjunction/templates`, `@memberjunction/templates-base-types`): Templates render as the user of each render. Pass that user as `ContextUser`; a render without one still runs, but an `{% AIPrompt %}` tag fails it.
- **`MaxRows: 1` reads report one row** (`@memberjunction/generic-database-provider`): A full `MaxRows: 1` read now reports `TotalRowCount: 1` rather than the view's total. Read two rows when you need to know whether more exist.
- **Duplicate runs need an Entity Document** (`@memberjunction/core-entities`, `@memberjunction/server`): `MJ: Duplicate Runs.EntityDocumentID` is required. The migration backfills existing runs and deletes runs whose entity has no document. Entity Documents no longer cascade deletes, so a document with runs or synced vectors cannot be deleted.
- **Recording-ledger fields are read-only on entity saves** (`@memberjunction/core-entities`, `@memberjunction/core-entities-server`): `MJ: AI Agent Sessions` drops the setters and GraphQL inputs for the seven `Recording*` ledger fields (`RecordingStartedAt` stays). Apply the whole release with `mj migrate`; the migration and the metadata sync must land together, or session saves fail.
- **Migrations** (`@memberjunction/migrations`, `@memberjunction/migrations-pg`): Schema and metadata migrations for bound data access and approvals, calendar event links, the per-connection integration catalog, alternate base views, duplicate-run documents, the content pipeline, delegated-OAuth gates on communication providers, composite performance indexes and CodeGen field repairs apply on `mj migrate`. On PostgreSQL, the three base-view column gaps tracked in [#5649](https://github.com/MemberJunction/MJ/issues/5649) remain.
