# IS-A entity batch hydration, cross-line migrations, and integration paging

## TL;DR
Eliminates N+1 database queries during IS-A entity hydration using in-memory engine and batch cache resolution. Plus CLI migration selection, integration record-map stack overflow, and React test harness fixes.

## Improvements
- **IS-A parent and child entity hydration resolves from in-memory engine and batch caches** (`@memberjunction/core`, `@memberjunction/core-entities`): Eliminates N+1 `RunView` and `RunViews` database queries during IS-A parent/child entity hydration. Upward IS-A parent hydration and downward IS-A child discovery first resolve records from caller-supplied batch caches (`batchUnfilteredCache`) or registered in-memory `BaseEngine` caches (including `_dataMap` properties populated mid-`Config()`). When an uncached child target requires a query on providers lacking batch discovery, per-entity calls collapse into a single level-by-level `RunViews` batch query with `WHERE [PK] IN (...)` filters. Sibling views in a `RunViews` batch are collected in a two-phase transformation before entity object conversion so parent and subtype entities in the same batch hydrate in memory with zero extra queries.

## Bug Fixes
- **Batched IS-A entity hydration fixes cache validation, mirror field state, and subtype fallbacks** (`@memberjunction/core`): `FindCachedEntity` no longer serves permission-denied or unfulfilled engine properties as valid cache hits, and batched child reads set `IgnoreMaxRows`. Batch-linked child entities hydrate inherited mirror fields from the parent so edits capture actual prior values, retaining their own `__mj_` timestamps and ancestors' virtual columns. Missing known-subtype parents fall back to database reads without re-querying unchanged children, and subtype-hint misses log consistently with the per-row path while failed reads are excluded from miss reporting.
- **`mj migrate` selects unapplied migrations across release lines** (`@memberjunction/cli`): Upgrading a database from a release line no longer skips applicable migrations. Remote migration fetches select every versioned migration file above the database's highest baseline row that has not been applied, rather than ignoring files older than the newest applied version. When core migrations are pending that are older than the highest applied migration and `mj.config.cjs` does not set `outOfOrder`, `mj migrate` automatically enables `outOfOrder` for the run and logs each out-of-order file.
- **Large integration record maps page without call stack overflow** (`@memberjunction/integration-engine`): Resolves a `Maximum call stack size exceeded` error during full-sync orphan sweeps and full push operations on large record maps. The record map loader previously set `IgnoreMaxRows` (which dropped `MaxRows`), causing entire record maps (~126k rows) to be fetched in a single page and pushed via array spreading. Record maps are now paged using `MaxRows` and appended without array spreading.
- **Business Central GL entry amount computed from debit and credit fields** (`@memberjunction/actions-bizapps-accounting`): `GetGLEntries` no longer queries or filters on `amount`, which is absent from Business Central API v2.0 `generalLedgerEntry`. `amount` is now computed as `debitAmount - creditAmount`, with `MinAmount` and `MaxAmount` filters applied to the computed value after the read.
- **React test harness detailed failure reporting and linter scope tracking** (`@memberjunction/react-linter`, `@memberjunction/react-test-harness`): Test harness failure reports preserve detailed context instead of collapsing errors; field-access violations include suggested similar field names (`SimilarFields`) and valid field lists (`AvailableFields`), while component registration and harness setup failures trigger specific violation rules (`harness-setup-error`, `component-load-error`). Missing sandbox utilities yield `sandbox-utility-unavailable` warnings rather than critical failures. The React linter tracks query and view row usage across React state, effects (`useMemo`, `useState`), array spreads, and lodash iteratees (`sumBy`), resolving variables per scope to avoid false type collisions. High-volume "Invalid JSX element type" errors (25 or more) fail the run while valid component wrappers (`React.memo`, `forwardRef`, `lazy`, context) are ignored, and assertion helper regexes avoid quadratic backtracking on adversarial inputs.
- **Test harness tracks failed and pending dataAccess calls** (`@memberjunction/react-test-harness`): `BuildDataAccessRecord` records failed `dataAccess` results with `Success: false` and their corresponding `ErrorMessage` (preventing client-database timeouts from being logged as 0-row successes). `RunView`, `RunViews`, and `RunQuery` calls are recorded when they start so unfinished calls at test completion are reported as still running after N seconds.
