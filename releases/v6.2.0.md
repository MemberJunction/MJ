# Upgrading from 6.1: field-level security, typed decisions and MJ Query

## TL;DR
The cumulative upgrade note for moving from the 6.1 LTS line to the 6.2 LTS line, covering the Edge builds v6.2.0-edge.0 through edge.8 and the 6.2.1 respin. 6.2 adds Rubrics, record cloning, typed decisions, the Durable Work Queue, form contributions, conversation forks, telephony and meetings, the Chief of Staff agent, Alternate Base Views, the content pipeline, the MJ Query language, Video Studio, the Excel add-in, Diagnostic Bundles and anchored record comments, plus field-level security, SQL screening and realtime fixes.

**Upgrade Notes apply:** 74 to 77 SQL Server migrations depending on your 6.1 patch, several requests 6.1 accepted are now refused, saved queries need `mj query refresh`, local and duplicate-detection vectors need re-embedding, `Entity.Configuration` is replaced on core entities, and server and clients must move to 6.2.1 together.

6.2.0 was the candidate cut on 2026-11-04 from v6.2.0-edge.8 and was never installed. 6.2.1 is the current candidate; install 6.2.1, not 6.2.0. Fixes that already shipped to 6.1 users in 6.1.1 to 6.1.6 are listed once, at the end, and are left out of the sections above it.

MemberJunction 6.x is released under the [Business Source License 1.1](https://github.com/MemberJunction/MJ/blob/next/LICENSE); 5.x and earlier stay ISC. What the licence grants, and what needs certification, is in the [licence section of the v6 upgrade guide](https://github.com/MemberJunction/MJ/blob/next/UPGRADE-v6.0.md#license-change--read-this-first).

## Upgrade Notes

### Upgrade steps

1. **Before upgrading, record any `Entity.Configuration` you set on core entities.** The release metadata replaces the whole field on the 63 entities in `metadata/entities/.clone-configurations.json` and the 15 in `metadata/entities/.save-return-datestamps-only-entities.json`. Re-apply your settings afterwards, merged with the new `Clone` and `SaveReturnMode` keys. (#4585, #5846)
2. **Before upgrading, check for blockers.** A database with bizapps-common 5.47 installed cannot upgrade yet ([#4939](https://github.com/MemberJunction/MJ/issues/4939), still open); do not delete common's prompt model to get past it. Find active credentials whose `ExpiresAt` is in the past, since they now throw (see below). If you take inbound phone calls, set `telephony.inboundRunAsUserEmail`.
3. **If you are on 6.1.5 or earlier**, also do the 6.1.6 preparation: link actions to `MJ: Action Authorizations` for non-Owner users, and configure the read-only database login (`dbReadOnlyUsername` / `dbReadOnlyPassword`). See [Already required on the 6.1 line](#already-required-on-the-61-line).
4. **Upgrade every `@memberjunction/*` package to 6.2.1 together**, server and client. Several fixes have a client half and a server half that must match, and some 6.2 clients fail against an older server (search streams, `GetRecordDependencies`, the WebSocket idle window).
5. **Run `mj migrate` with the 6.2.1 CLI, in the same deploy as the 6.2.1 server.** The release's metadata-sync migrations must not land before the server code that guards them, and the recording-ledger migration and its metadata sync must land together. The 6.2.1 CLI turns on `outOfOrder` for that run when a 6.1 line database has backported migrations ahead of older 6.2 files; if your config sets `outOfOrder: false`, remove it for the upgrade. (#6151)
6. **If you regenerate code for your own entities, run `mj codegen` and review the output.** The CodeGen prompts moved to new models, so AI-written validators, descriptions and form layouts can differ. On SQL Server, numeric or single-value `IN (...)` CHECK constraints now generate literal union types instead of `number`. (#4920, #4003)
7. **Refresh saved queries.** Run `mj query refresh --all --dry-run`, fix what it lists as `Error` and `Warning`, then run `mj query refresh --all`. It never changes a query's SQL. (#6124)
8. **Re-embed local vectors.** Run `mj ai actions run -n "Re-embed Local Vectors" --param "Force=true"`, then restart MJ server processes. (#5214)
9. **Rebuild vectors and caches that held restricted data.** Once every server runs 6.2.1, flush RunView keys in any shared cache (Redis). Re-vectorize Entity Documents on field-secured entities (rebuilding external stores such as Pinecone), re-run entity autotagging, review tags produced from restricted text, and re-sync the vectors behind any duplicate detection. (#5968, #6033)
10. **Reload clients.** Reload open browser tabs, move pinned consumers of `@memberjunction/graphql-dataprovider` to 6.2.1, and replace any self-hosted `mj-widget.js`. If a proxy or gateway pins `Access-Control-Allow-Headers`, add `x-mj-timezone`.

There is no Node.js or Angular change: the distribution still requires Node 24 or later and Angular stays on 21.2.22. The new Video Studio render worker needs Node 22 or later and `ffmpeg` on `PATH`.

### Database migrations

- **SQL Server: 77 migrations were added between v6.1.0 and v6.2.0; a 6.1 database applies the ones it does not already have.** Three of them shipped on the 6.1 line under their 6.2 file names and are skipped if already applied: `V202609161850__v6.2.x__Metadata_Sync` (6.1.2), `V202609191819__v6.2.x__TaskGraph_Guarded_Write_Sprocs` (6.1.3) and `V202609291627__v6.2.x__MagicLink_Consume_Invite_Sproc` (6.1.5). A database on 6.1.5 or 6.1.6 applies 74; one on 6.1.0 or 6.1.1 applies 77. 6.2.1 adds none.
- **6.1.5 and 6.1.6 databases also applied the line-only `V202610061630__v6.2.x__Line_Metadata_Sync_Native_Tool_Calling`.** It has no file in 6.2 and needs none: `mj migrate` hands Skyway only the migrations the database has not applied.
- **Schema changes, by area.** AI and agents: `AIPromptRun.UserID`, `decimal(19,8)` cost precision and `vwAIUsageFacts`; `AIVendor.Configuration`; Decision step types for agents, tasks and entity-document reasoning; the `Handoff` step type and agent consults; `AIAgentRunStep` payload source-step pointers and `AIPrompt.TemplateDataCapture`; `MJ: AI Agent User Policies` and the `AgentWake` routine type; `ActionParam.ValueSchema`; `AIAgentSession` close reasons and the recording shard ledger; cascade deletes for AI agent configurations. Data platform: Record Change clone context and `MJ: Record Clone Logs`; the Rubrics schema and views; `MJ: Entity Form Contributions`; binary vector columns; the work queue schema and its guarded-write procedures; `MJ: Entity Alternate Base Views`; bound data access and query approvals; the content pipeline; query extraction metadata and detection methods; `Entity.AutoUpdateDisplayName`; `SaveReturnMode` datestamps-only procedures; the per-connection integration catalog; composite performance indexes and the RecordChange recycle-bin index; CodeGen `EntityField` drift repairs; the Semantic Graph entities. Collaboration and UI: `Project.OwnerUserID` with its row-level-security filter and a legacy backfill, then the three-tier folder permission backfill; `MJ: Conversation Branches`; anchored conversation and record comment columns; `User.IsTemplate`; `MJ: Scoped Notification Configs`; the login screen on themes; Calendar Event Links; Brand Kits and Video Archetypes; `MJ: Diagnostic*` entities. Operations: Feature Pipelines and their types, keys and versions; `Archive.StorageMode`; `spSetScheduledJobNextRunAt`; telephony phone numbers, number pools and interactions; communication-provider delegated OAuth gates; web search providers; the hardened `spDeleteEntityWithCoreDependencies`, which now also clears graph edges.
- **Data changes.** Ten `Metadata_Sync` migrations carry the release metadata (the first of them is the one 6.1.2 already applied), including the `Entity.Configuration` replacements above. One migration deletes 25 obsolete computer-use Test records; one repoints the duplicate `STT` model type onto `Speech to Text`; one backfills `MJ: Duplicate Runs.EntityDocumentID` and deletes runs whose entity has no Entity Document.
- **Metadata_Sync migrations now update only the fields MJ changed** (#5177). Migrations published before this release still contain full-row updates, so if you tune MJ-owned rows (for example `TrustServerCacheCompletely`), re-apply those settings after migrating.
- **PostgreSQL has counterparts for these migrations, with two known gaps.** `vwEntities` and `vwEntityFields` still lack the `EnableFieldLevelSecurity`, `RelatedEntityFilter` and `RelatedEntityOrderBy` columns, so that field metadata is removed on PostgreSQL installs ([#5649](https://github.com/MemberJunction/MJ/issues/5649), still open). The two `EntityFormContribution` unique indexes include nullable columns, so PostgreSQL accepts two Active Role or Global contributions with the same key where SQL Server refuses the second. 6.2.1 does not change this.

### Breaking changes and required actions

**Security and access control**
- **Field-level security refuses more** (`@memberjunction/core`, `@memberjunction/server`, `@memberjunction/generic-database-provider`, `@memberjunction/templates`, `@memberjunction/a2aserver`, and others): client input naming a field the caller cannot read is rejected instead of dropped. Ad-hoc SQL from any user except the system user may read only entity base views the caller reads with no row filter and no denied field, and ad-hoc SQL with no user is refused. For a user with any field denial, a saved query without a role-list grant is refused when it reads anything other than an entity base view or table; grant such queries through `MJ: Query Permissions` after reviewing their SQL. REST `runView` / `runViews` always return `simple` rows. An entity communication skips recipients whose address field the sender cannot read. Without `a2aServerSettings.userEmail` the A2A agent card lists no entities or agents. (#5968)
- **Template renders need their user** (`@memberjunction/templates`): templates render as the user of each render; pass that user as `ContextUser`. A render without one still runs, but an `{% AIPrompt %}` tag fails it, and an `{% AIPrompt %}` tag whose model fails now fails the render, so a communication that used to send with an error in its body does not send. (#5968)
- **Expired credentials are refused** (`@memberjunction/credentials`, `@memberjunction/ai-prompts`): a credential past its `ExpiresAt` throws `CredentialExpiredError` where it used to resolve. `CredentialEngine.Instance.ExpirationConfig` accepts `policy: 'warn'` or a `graceMs` for a staged rollout. (#4058)
- **Scoped searches are bounded by their configuration** (`@memberjunction/search-engine`): a scope with no enabled provider rows, or no lanes of a kind, returns nothing instead of searching everything, and an inactive, expired or missing scope refuses the search. Custom search providers that read entity or storage lanes must override `ConsumesLaneKinds`. A `required` scope dimension that resolves to nothing refuses with `ScopeDimensionError`, and a storage lane `FolderPath` that renders empty or contains `..` refuses the search. A lane `ExtraFilter` now applies to every provider's hits. To keep a scope's old reach, add one enabled `MJ: Search Scope Providers` row per provider it should run. Streamed per-provider events carry only a `ResultCount`, so upgrade MJAPI before clients. (#5175)
- **Agent runs check scope permissions** (`@memberjunction/ai-agents`, `@memberjunction/server`): pre-execution RAG searches an agent's assigned scopes only for users with a `Search` or `Manage` grant on the scope (or an agent set to `All`). `PrimaryScope*`, `SecondaryScopes` and `__agentTypePromptParams` in a run's `data` are dropped unless the caller is the system user or an API key holding the new `agent:trusted` scope.
- **Workflow actions refuse inside agent runs** (`@memberjunction/core-actions`): Loop, Parallel Execute, Conditional and Retry refuse inside any agent run, since the actions they run cannot carry the run's scope. Agents configured to call them need another path.
- **Storage routes check account permissions** (`@memberjunction/server`): the GraphQL storage routes need Read or Write on the storage account and refuse files the caller cannot read. Accounts with no `MJ: File Storage Account Permissions` rows stay open.
- **More client SQL is refused** (`@memberjunction/generic-database-provider`, `@memberjunction/server`): beyond the 6.1.6 screening, a backslash inside a quoted string or identifier in a client `ExtraFilter`, `OrderBy` or `OverrideExcludeFilter` is refused, so a filter such as `Account = 'DOMAIN\user'` now fails; stored view clauses are not checked for backslashes.
- **Server-only fields and rows** (`@memberjunction/core-entities`, `@memberjunction/core-entities-server`, `@memberjunction/server`): people post conversation messages only as themselves, and a message whose `ID`, conversation or rating comes from a TransactionGroup variable is refused, so creating a conversation and its first message in one transaction group no longer works; save the conversation first (#5299). The seven `Recording*` ledger fields on `MJ: AI Agent Sessions` lose their setters and GraphQL inputs (`RecordingStartedAt` stays) (#6020), and only the server's own close paths can set `TimeLimit`, `Idle`, `Janitor` or `Shutdown`. Record Changes can be annotated, but an update may change only `Comments` and requires `Record Changes: Annotate`.
- **Inbound phone calls need a run-as user** (`@memberjunction/telephony-adapters`): inbound calls run as `telephony.inboundRunAsUserEmail` instead of the System or Owner user, and are rejected when it is missing. (#5023)
- **Shared forms need `Manage Form Defaults`** (`@memberjunction/core-entities-server`): changing or deleting an existing Role or Global custom form requires that authorization, and an `mj sync push` of Global rows needs a sync user who holds it or is an Owner. (#4311)
- **Web widget and anonymous sessions** (`@memberjunction/server`, `@memberjunction/realtime-widget`, `@memberjunction/ng-realtime-widget`, `@memberjunction/livekit-room-server`): a guest token refresh needs a proof signed by a key the widget registers, so a widget bundle older than this release gets 403 at its first refresh. The widget needs its host page on HTTPS (or `localhost`). A widget whose guest role is the stock `UI` role is refused with `guest_role_not_isolated`; use `Widget Guest` or a role listed in `magicLink.grantableRoleNames`. Guest sessions end 12 hours after their first mint, and anonymous sessions started before the deploy must start again. (#5997, #6065)
- **`SetupRESTEndpoints` defaults to disabled** (`@memberjunction/server`): code that calls it directly without `enabled` no longer mounts the REST API; pass `enabled: true`. A standard MJAPI deployment is unchanged. With `requireAuth` on, the component registry server refuses requests until a subclass overrides `checkAPIKey`. (#6034)

**Queries, views and data access**
- **Composed queries receive only the arguments in their reference, and results change silently** (`@memberjunction/sql-parser`, `@memberjunction/core-entities-server`): a query that relied on a same-named parameter flowing into a composed query now runs without error and returns the inner query's unfiltered rows. The `mj query refresh` dry run lists these as `Warning` (`MJQ_COMPOSITION_IMPLICIT_ARGUMENT`). Fix each by naming the argument, as in `{{query:"Path/Name(Since=Since)"}}`. (#6124)
- **Queries with a template tag inside quotes stop running** (`@memberjunction/sql-parser`, `@memberjunction/core-entities-server`): a value tag inside a SQL string (`WHERE Region = '{{ Region }}'`) or a quoted identifier is refused on every run. Template syntax outside the MJ Query language (macros, includes, function calls, unknown filters, `Context.*` tokens) and queries that write or run more than one statement are also refused. A query naming a field the user may not read is refused with the "does not exist or you do not have permission" message, so code matching the old "Denied entities" text must change. (#6124)
- **`RunView` `TotalRowCount` is optional** (`@memberjunction/core`, `@memberjunction/generic-database-provider`, `@memberjunction/graphql-dataprovider`): `RunViewResult.TotalRowCount` is `undefined` whenever `SkipTotalRowCount: true` is passed; strict TypeScript consumers that read the field get a compile error. Callers that read only `Results` should pass `SkipTotalRowCount: true`. `MaxRows: 1` behaves as it did in 6.1. (#6226)
- **`RunView` omits binary fields by default** (`@memberjunction/core`): pass `IncludeBinaryFields: true`, or name the field in `Fields`, to get them. `Load()` still includes them. (#4978)
- **GraphQL saves return only what changed** (`@memberjunction/graphql-dataprovider`, `@memberjunction/server`): an Update sends and receives the fields it changed plus computed and virtual ones, so a client's copy no longer picks up another user's concurrent edits to fields it did not change. Conflicting concurrent edits to the same field fail with `CONCURRENT_MODIFICATION_CONFLICT`. (#5807, #5865, #6183)
- **`GetRecordDependencies` needs a 6.2 server** (`@memberjunction/server`, `@memberjunction/graphql-dataprovider`): the client reads `PrimaryKey`, which older servers do not return. `CompositeKey` stays as a deprecated alias.
- **Mixed-version clients drop renamed metadata fields**: metadata fields such as `EntityInfo.spCreate` serialize under PascalCase names, which a client older than its server drops. Public APIs across most packages gain PascalCase names; the old names remain as `@deprecated` forwarding stubs.
- **Duplicate detection needs its document and fresh vectors** (`@memberjunction/core-entities`, `@memberjunction/ai-vector-dupe`, `@memberjunction/ai-vector-sync`, `@memberjunction/ai-vectors-memory`): `MJ: Duplicate Runs.EntityDocumentID` is required. Entity Documents no longer cascade deletes, so a document with runs or synced vectors cannot be deleted; set it Inactive. Vectors synced before this release carry no `EntityDocumentID`, so a run against them fails until they are re-synced. The in-memory vector store now scores standard cosine similarity; re-tune thresholds set against it to `2 × old − 1`. (#6033)
- **Local embedding vectors change** (`@memberjunction/ai-local-embeddings`, `@memberjunction/aiengine`): the move to `@huggingface/transformers` 4.3.1 changes all-mpnet-base-v2's vectors under the same model ID, and long texts are truncated at the model's `MaxInputTokens`. Re-embed as in the upgrade steps. (#5214)

**AI and agents**
- **Agent replies are created by the server** (`@memberjunction/server`, `@memberjunction/graphql-dataprovider`, `@memberjunction/ai-agent-client`, `@memberjunction/conversations-runtime`, `@memberjunction/ai-agents`, `@memberjunction/task-graph`): `RunAIAgentFromConversationDetail` takes `userMessageId` instead of `conversationDetailId`, and the server creates the reply row. Client code that creates or edits `AI`/`Error` rows in `MJ: Conversation Details` is refused, and `RunAIAgent` / `RunAIAgentSystemUser` no longer write into a caller-supplied `conversationDetailId`. `AgentClientSession.RunAgentFromConversationDetail` takes `UserMessageId`, and `TaskContinuationParams.SubmittedByUserID` is required. (#6001)
- **Prompt model selection enforces the LLM type** (`@memberjunction/ai-prompts`): a prompt whose `AIModelTypeID` names a non-LLM type, or an explicit override naming a model of another type, fails with an error naming both types. Prompt model bindings pointing at another type are skipped and logged. No shipped prompt is affected.
- **Prompt and agent runs store less** (`@memberjunction/ai-prompts`, `@memberjunction/ai-agents`): `AIPromptRun.Messages` holds no `data` or `templateData` by default; set `TemplateDataCapture` to `Referenced` or `Full` where you need them. Agent runs no longer write `AIAgentRun.Result` (use `FinalPayload`), and readers of `AIAgentRunStep.PayloadAtStart` / `PayloadAtEnd` must follow `PayloadAtStartSourceStepID` / `PayloadAtEndSourceStepID` when set. (#5526, #5653)
- **`BeforeAgentTurn` fires on every route**, once per turn before any reply row exists, carrying the resolved agent and route; a cancel leaves nothing behind. (#4788)
- **Removed or changed AI APIs**: `AIPromptRunner`'s protected `buildFailoverCandidates` and `createCandidatesFromModels` are removed. `PayloadFeedbackManager.QueryAgent` takes a `PayloadFeedbackContext` (#4848). Conversation-routing builders and `IsAgentAllowed` move from `@memberjunction/ng-conversations` to `@memberjunction/ai-core-plus` (#4860). `IRealtimeSession.SendInput` takes one `RealtimeInputFrame` (`{ Data, Kind, MimeType?, TimestampMs? }`) instead of `(chunk, kind?)` (#5090). `IRealtimeSessionRecorder` returns Opus packets (`TakeEncodedPackets()`, `Stop(): Promise<number>`), and `BrowserRecordingUnloadGuard` is removed; hosts that wire their own page-lifecycle events call `SendRecordingTerminal` (#5536).
- **`Web Search` is a provider-neutral router** (`@memberjunction/web-search-engine`, `@memberjunction/core-actions`): direct agent bindings to `Google Custom Search` and `Perplexity Search` are removed by the metadata migration in favour of the routing `Web Search` action. (#4488)
- **CodeGen prompts and rank-based model choice move to new models** (`@memberjunction/codegen-lib`, `@memberjunction/aiengine`): prompts and agents that choose models by rank may pick a different model. (#4920)

**Angular and UI**
- **Conversation thread-panel API removed** (`@memberjunction/ng-conversations`, `@memberjunction/ng-explorer-core`): forks replace the ParentID-based thread panel. `ThreadPanelComponent`, the chat area's `ThreadId` input and `ThreadOpened`/`ThreadClosed` outputs, the workspace's `OpenThread`/`CloseThread`/`SelectedThreadId`, and `MessageListComponent`'s `ReplyInThread`/`ViewThread` outputs are removed with their camelCase aliases. (#5179)
- **`UserInfoEngine.UserRecordLogs` removed** (`@memberjunction/core-entities`): use `await UserInfoEngine.LoadRecentRecordLogs(n)`. `GetRecentRecordsForEntity()` is removed. (#5141)
- **Legacy `mj-btn-*` classes removed** (`@memberjunction/ng-explorer-app`): `.mj-btn-primary`, `-secondary`, `-ghost`, `-icon-only`, `-sm`, `-lg`, the unused `.mj-modal-*`, `.mj-icon-card*`, `.skip-icon*` and `.k-*` rules and `_md3-shared.css` are gone; use `mjButton` or `mj-btn--<variant>`. (#5082)
- **Chief of Staff pages and exports removed** (`@memberjunction/ng-dashboards`, `@memberjunction/ng-base-application`): priorities, objectives, milestones, assignments and to-dos move to an extension in the BizApps Tasks app. `@memberjunction/ng-dashboards` drops `ChiefOfStaffDashboardComponent`, `LoadChiefOfStaffDashboard`, the task scope, priority, to-do and health helpers, the `BIZAPPS_*` entity names and the tab helpers, and renames `BuildCockpitScopeFilters`, `COCKPIT_LIVE_ENTITIES` and `IsCockpitEntityChange` to their `ChiefOfStaff` forms.
- **Conversation folders default to Private** (`@memberjunction/core-entities`, `@memberjunction/ng-conversations`, `@memberjunction/server`): a conversation in a Shared or Public folder is visible only to its owner unless `inheritFolderAccess: true` is set in its `AdditionalData`. (#6187)

**Integrations, packages and tooling**
- **New integration objects and columns arrive disabled** (`@memberjunction/server`): `autoEnableNewObjects` and `autoEnableNewColumns` default to `false`; pass `true` to adopt them automatically. (#4141)
- **Integration field-map API removed** (`@memberjunction/integration-engine-base`, `@memberjunction/integration-engine`): `IntegrationEngineBase` loses the `FieldMaps` getter, `GetFieldMapsForEntityMap` and the `FieldMaps` option of `SeedForTesting`. Use `LoadFieldMapsForEntityMap(entityMapID, contextUser?)`, which throws when the read fails. (#6208)
- **Open App manifests and Node-only packages** (`@memberjunction/open-app-engine`, `@memberjunction/dynamic-packages`): a `role: "actions"` package under `shared` no longer reaches the browser build, and one under `client` is rejected. Add `"platform": "node"` to other Node-only `shared` packages or move them to `server`. `mj app install` and `upgrade` check that app packages exist on npm before changing anything, so run `npm login` if private-package lookup fails. (#4521, #6109)
- **`@memberjunction/server` types point at `dist`**: its `types` entry and export condition are `dist/index.d.ts`. (#6153)
- **Failover attempt limit and Anthropic `max_tokens`** (`@memberjunction/ai-prompts`, `@memberjunction/ai-anthropic`): `FailoverMaxAttempts` now caps the requests a failover sends, where it was ignored (#4463). Anthropic streaming requests without `max_tokens` default to 32000, so Claude 3 models need an explicit value (#6046).

### Already required on the 6.1 line

These changes shipped in 6.1.4, 6.1.5 or 6.1.6 with their own upgrade notes. If you are on 6.1.6 you have already handled them; from an earlier 6.1 patch, read [v6.1.4](v6.1.4.md), [v6.1.5](v6.1.5.md) and [v6.1.6](v6.1.6.md).

- Cache-invalidation events carry row data only for entities in `cacheSettings.recordDataBroadcastEntities` (6.1.4, #4595).
- Durable tasks queued with the old array payload fail loudly; re-trigger them or use **Edit input & retry** (6.1.5, #4796).
- `RunAction` authorizes each action through `MJ: Action Authorizations`, template rendering is sandboxed and template runs are authorized, RunView aggregate expressions are restricted, the realtime relay ignores a session's editable `Config`, SQL data context items and dataset reads apply the caller's permissions, client filters are screened, and record names follow field- and row-level security (6.1.6, #5264 to #5273).
- Ad-hoc SQL, the Run Ad-hoc Query action and SQL data context items need the read-only database login (6.1.6).
- Gemini and Vertex prompts that set an effort level now think at that level (6.1.6, #5590).
- The realtime WebRTC broker endpoint is on by default; set `MJ_REALTIME_ENABLED=false` to turn it off (6.1.2, #4512).

## New Features

**AI, agents and decisions**
- **Typed decisions** (`@memberjunction/ai`, `@memberjunction/ai-prompts`, `@memberjunction/ai-agents`, `@memberjunction/task-graph`, `@memberjunction/ng-flow-editor`, `@memberjunction/server`): a `Decision` model type and `AIDecisionRunner` answer Likelihood, Choice and Score questions with a probability per answer, model selection, failover and prompt-run telemetry, exposed through the `Run Decision` action and `RunDecision` mutation. Flow agents and task graphs gain Decision steps; Loop agents can use decisions behind a master switch, `decisionsEnabled`, off by default; duplicate detection gains `Decision` and `DecisionThenPrompt` modes. Decision drivers ship for Cloudflare, System One, Perplexity, OpenAI's Decisions API, Subquadratic and Inception Labs. (#4814, #4874, #4855, #4983, #4999, #5537, #5611)
- **Rubrics** (`@memberjunction/rubrics-base`, `@memberjunction/rubrics`, `@memberjunction/ng-rubrics`, `@memberjunction/testing-engine`): score any record against versioned, weighted criteria with LLM, agent, deterministic, Decision or human evaluators and consensus views. Published versions are frozen. Explorer gains a Rubrics application, tests can select a rubric through `RubricID`, and seven shipped agent rubrics bind to their agents. `MJ: Test Rubrics` is deprecated. (#4937, #4984)
- **Chief of Staff agent and per-user agent policies** (`@memberjunction/ai-agents`, `@memberjunction/scheduling-engine`, `@memberjunction/ng-dashboards`): a personal Chief of Staff agent with an Explorer cockpit for approvals and wakes. `MJ: AI Agent User Policies` narrows what an agent may do for one user below that user's own permissions, and `AgentWake` routines let an agent schedule its next wake. (#5842, #6041)
- **Agent runs bounded by their audience, bound action parameters and host-assigned scopes** (`@memberjunction/ai-agents`, `@memberjunction/ai-core-plus`): server code can name everyone who will see a run's output (`ExecuteAgentParams.Audience`), fix action inputs the model cannot see or change (`boundActionParams`), and limit a run to given search scopes (`SearchScopeIDs`). (#5175, #6234)
- **Sub-agent consults and Sage handoffs** (`@memberjunction/ai-agents`, `@memberjunction/ng-conversations`): a sub-agent can consult its caller and escalate to `MJ: AI Agent Requests`; Sage can hand a conversation to a specialist agent and take it back on an `@Sage` mention.
- **Native tool calling for the Loop agent and JSON Schema for action parameters** (`@memberjunction/ai-agents`, `@memberjunction/ai-prompts`, `@memberjunction/ai-anthropic`, `@memberjunction/ai-gemini`, `@memberjunction/ai-openai`): the Loop agent can run as a provider-native tool loop, and `ActionParam.ValueSchema` declares a parameter's shape for the tool declaration and argument coercion. (#5965, #5848)
- **Runners for embeddings, images, reranking, speech and video** (`@memberjunction/ai-prompts`, `@memberjunction/ai-reranker`): each selects a model from a prompt's bindings, resolves its credential, fails over and records an AI Prompt Run, as chat prompts already did. (#4842, #4843, #4844, #4909)

## Improvements

- **Prompt caching and cost on Loop agents** (`@memberjunction/ai-agents`, `@memberjunction/ai-prompts`): per-iteration state moves out of the system prompt into a trailing `<mj-runtime-state>` message, so provider prefix caches stay warm; measured cached input rose to 66–96% and prompt cost per million tokens fell 37–80%. (#5800)
- **Agents stop retrying tools that cannot succeed** (`@memberjunction/ai-agents`): a run-scoped circuit breaker disables an action after a fatal configuration error, two identical failing calls or five consecutive failures.
- **Faster saves and reads** (`@memberjunction/sqlserver-dataprovider`, `@memberjunction/generic-database-provider`, `@memberjunction/core`): SQL Server saves use typed parameters so one plan is reused per entity and field set; `SkipTotalRowCount` skips the count query; RunView batches its queries and reads only the columns asked for; IS-A subtypes and parents resolve from caches; cross-replica invalidation sends row deltas; and an idle MJAPI stops polling its database. (#5777, #4025, #4450, #4787, #6271, #6186)
- **Transactions stay with the caller that opened them** (`@memberjunction/generic-database-provider`, `@memberjunction/core`): a transaction opened on a shared provider belongs to its async scope, so concurrent requests no longer run inside someone else's transaction. (#4798)
- **Caches hold large datasets and stay consistent** (`@memberjunction/core`, `@memberjunction/server`): the per-entry ceiling is derived from the budget (75% by default, was a fixed 25%), cached RunQuery results are tied to the query definition, and 22 log, run and audit entities stop taking part in caching. (#4445, #5703, #5141)
- **Search ranks multi-source results by Reciprocal Rank Fusion** (`@memberjunction/search-engine`, `@memberjunction/ng-search`). (#4993)
- **Integration sync accuracy and memory** (`@memberjunction/integration-engine`): reported counts match what a sync did, discovery stops at a memory budget, large syncs release response pages (over 2 GB saved), and deactivating a connection pauses its schedules. (#4455, #4617, #6266)
- **SQL dialect follows the database** (`@memberjunction/sql-dialect`, `@memberjunction/ai-agents`): agents on PostgreSQL get PostgreSQL syntax. (#4431)
- **`mj sync` keeps `@env:` references and pushes portable SQL** (`@memberjunction/metadata-sync`): pull no longer writes resolved secrets into files, `@lookup` values become natural-key subqueries, and deletes run in dependency order. (#5884, #6069)

## Bug Fixes

- **A durable action's submission log row survives the save that queued it** (`@memberjunction/core`, `@memberjunction/generic-database-provider`, `@memberjunction/actions`, `@memberjunction/sqlserver-dataprovider`): fixed in 6.2.1. With a durable submitter registered, ActionEngine's log row was queued inside the save's transaction and rejected after commit, so the run left no Action Execution Log row (#6251). `BaseEntitySaveQueue` gains an opt-in `detachFromTransaction` option that only ActionEngine's log queue uses. (#6351)
- **Records saved in a rolled-back transaction no longer stay cached** (`@memberjunction/core`): engine cache changes raised inside a transaction apply on commit and are dropped on rollback, using pre-delete primary keys.

- **Agent replies survive a WebSocket that dies without closing** (`@memberjunction/graphql-dataprovider`, `@memberjunction/ng-conversations`, `@memberjunction/server`, `@memberjunction/redis-provider`): the client detects a silent socket within about 14 seconds, reconciles over HTTP, and status reaches the browser across replicas through Redis. (#4540)
- **Anonymous visitors isolated from each other** (`@memberjunction/server`, `@memberjunction/livekit-room-server`): every anonymous guest shared one Anonymous user, so a visitor who learned another's session ID could relay into, close or restore it.
