# ActionEngine execution-log save detachment from ambient caller transactions

## TL;DR
A patch release for the certified lts/6.2 line. Fixes ActionEngine execution-log persistence when queued inside active caller transactions.

## Bug Fixes
- **ActionEngine execution-log saves detached from caller transaction** (`@memberjunction/actions`, `@memberjunction/core`, `@memberjunction/generic-database-provider`, `@memberjunction/sqlserver-dataprovider`): when an `After*` `Durable` Entity Action was queued from inside an active save transaction, `ActionEngine`'s fire-and-forget "Submitted for durable execution" log row inherited the caller's transaction handle. Because caller code does not await log writes, the queued statement reached SQL after the caller's transaction issued its `COMMIT`, failing with `The ambient transaction ended before this query ran` and dropping the Action Execution Log row. `BaseEntitySaveQueue` now supports an opt-in `detachFromTransaction` option that executes writes via `IEntityDataProvider.RunOutsideAmbientTransaction` on the connection pool, and `ActionEngine`'s log queue enables it so execution logs commit independently. Other queues—such as agent run steps, AI prompt runs, and process run details—remain attached to the caller's transaction because their owners flush them before commit and their rows reference uncommitted transaction data.
