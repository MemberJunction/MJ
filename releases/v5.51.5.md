# Row-level security update validation, API-key scope refresh, and dropdown accessibility

## TL;DR
Row-level security update validation, periodic API-key scope cache refreshing, and dropdown accessibility improvements for the certified 5.x line. Plus RLS numeric parsing and NULL column projection fixes.

## Improvements
- **`mj-dropdown` accessibility and shell search dropdown naming improved** (`@memberjunction/ng-ui-components`, `@memberjunction/ng-explorer-core`): `mj-dropdown` gains `AriaLabel`, `AriaLabelledBy`, `InputId`, and `AriaDescribedBy` inputs, which are applied to the trigger and popup listbox and composed into the filter box's accessible name. The dropdown points `aria-controls` at its listbox while open and removes disabled controls from tab focus. The filter box placeholder text now reads `"Filter..."` instead of `"Search..."`, and the Explorer shell's global search dropdown is explicitly named `"Search in"` (#4337).

## Bug Fixes
- **Updates are checked against row-level security using new values** (`@memberjunction/core`, `@memberjunction/generic-database-provider`): updates are now checked against row-level security filters using the row's modified values as well as the stored row. Previously, a user whose Update permission carried a row-level security filter could open a record they were permitted to edit, change the column tested by the filter (such as organization), and save it, moving the record outside their scope. That save is now refused with `"the requested changes would move this record outside your permitted row scope"`. Saves that keep the record in scope behave as before (#5783).
- **Row-level security evaluation projects NULL columns as typed expressions** (`@memberjunction/core`, `@memberjunction/generic-database-provider`): the row representation tested by Update and Create checks now projects NULL columns as typed `CAST(NULL AS <type>)` expressions mapped through the provider's SQL dialect. Previously, NULL columns were omitted from the test row, causing filters that referenced them to fail with `Invalid column name` and breaking valid in-scope saves when filters used `OR` logic across multiple roles where a column in another branch was NULL.
- **Row-level security Create checks validate numeric field values** (`@memberjunction/generic-database-provider`): the RLS Create check now parses and validates numeric field values before rendering them. A save attempting to set an unparseable numeric value fails with `"value for numeric field <name> does not parse as a number"`.
- **API-key scopes and applications are re-read from the database periodically** (`@memberjunction/api-keys`, `@memberjunction/api-keys-base`, `@memberjunction/core`, `@memberjunction/integration-test-suite`): API-key scope, application, and key-binding tables are re-read from the database every `scopeCacheTTLMs` (default 60 seconds). A scope removed or an application deactivated by another process now stops granting access within one TTL instead of requiring a server restart. The refresh rebuilds the engine's lookup maps, and `BaseEngine` expiry ticks now read directly from the database instead of the server cache. Additionally, a failed tick re-arms the timer instead of stopping refreshes, a failed initial load still schedules the refresh timer, setting the interval to 0 stops the timer, and expiry timers use unreferenced handles so they no longer prevent Node process exit (#5921).
