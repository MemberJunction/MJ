# Security-hardened cache invalidation, resilient picker dismissals, and grid export fixes

## TL;DR
Cache-invalidation events are hardened to withhold raw row data by default, ensuring robust data isolation across connected sessions. This release resolves tab navigation freezes and foreign-key lookup bugs, plus grid export and React test harness fixes.

**Upgrade Notes apply:** cache invalidation events withhold raw row data by default, which triggers full-view reloads for AutoRefresh entities unless allowed.

MemberJunction 6.x is released under the [Business Source License 1.1](https://github.com/MemberJunction/MJ/blob/next/LICENSE); 5.x and earlier stay ISC. What the licence grants, and what needs certification, is in the [licence section of the v6 upgrade guide](https://github.com/MemberJunction/MJ/blob/next/UPGRADE-v6.0.md#license-change--read-this-first).

## Improvements
- **Grid exports and workspace toolbar communication options aligned with rendered layouts and capabilities** (`@memberjunction/ng-entity-viewer`): Grid exports now construct Excel columns from the active, rendered AG Grid state—honoring on-screen ordering, visibility, and user-defined headers—rather than the static, host-declared column list. This ensures that custom column orderings or saved states are accurately exported. Exported columns also omit pixel widths, allowing Excel to auto-fit them natively rather than misinterpreting pixels as character widths. In addition, the "Send Message" action is now conditionally displayed only for entities that support communication (verified by checking for an active Entity Communication Message Type in the local provider). Finally, the grid's entity-action auto-loader now queries the local provider's `EntityActionEngineBase` rather than the global singleton.
- **React test harness implements query row caps and detailed data access tracking** (`@memberjunction/react-test-harness`): Components running under the test harness could previously request unbounded datasets because `RunQueryParams.MaxRows` lacked a default, causing massive queries (up to 200,000+ rows) to exhaust the node/browser heap during JSON serialization. To prevent out-of-memory errors, `__mjRunView`, `__mjRunViews`, and `__mjRunQuery` now clamp `MaxRows` to `ComponentExecutionOptions.dataCaps` (defaulting to 1,000). To aid debugging, `ComponentExecutionResult.dataAccess` now tracks and returns the execution metrics of each call—including row counts, capping status, and duration—and capped calls raise a `data-row-cap` warning. Target resolution for views and queries has also been aligned with core runtime behavior (prioritizing `QueryID` and using category-qualified paths). Finally, the HTML truncation backstop was reduced from 100MB to 25MB, and an unused working file `component-linter.ts.working` was deleted.

## Bug Fixes
- **Cache-invalidation subscription hardened to prevent unauthorized row-data leaks** (`@memberjunction/server`, `@memberjunction/core`, `@memberjunction/core-entities`, `@memberjunction/ng-core-entity-forms`, `@memberjunction/ng-dashboards`): The `cacheInvalidation` subscription was previously broadcast to all connected clients without any per-user filtering, attaching the complete serialized row data (`JSON.stringify(entity.GetAll())`) to every save. This bypassed row-level security and allowed any signed-in session to receive sensitive data they had no right to read. To close this leak, `recordData` is now only populated on the server for entities explicitly permitted via the new `cacheSettings.recordDataBroadcastEntities` configuration list (defaulting to `[]`, while `['*']` restores the legacy behavior). `EntityName` and `PrimaryKeyValues` continue to broadcast unconditionally as they are non-sensitive identifiers. Consumers requiring row details now resolve them securely via the new `ResolveEntityEventRow()`, which re-reads the record by primary key through the provider as the signed-in user, returning `null` if read access is denied. Consumers such as the `ConversationEngine`, AI Agent Run forms, and Form Builder cockpit have been updated to securely re-read row details as needed, ensuring remote updates do not fail silently when `recordData` is withheld.
- **Delete options schema input made optional on the wire again** (`@memberjunction/server`): Since version 6.1.0, the `DeleteOptionsInput.SkipRecordChanges` field was required (`Boolean!`), which broke backward compatibility with existing 5.51.x clients. Any older client specifying deletion options would fail GraphQL schema validation with a `Field "DeleteOptionsInput.SkipRecordChanges" of required type "Boolean!" was not provided` error. The field is now optional again on the wire and defaults to `false` (which matches the server's existing fallback), restoring full compatibility for older clients.
- **Foreign-key picker dropdown hardened against async lookup and focus bugs** (`@memberjunction/ng-base-forms`): Previously, dismissing the foreign-key picker panel (via blur or Escape) left any active database search in flight. When the results arrived, they would reopen the dropdown panel with nothing focused. Because the input was blurred, Escape could not close it, and there was no outside-press handling, trapping the user until they selected a row or scrolled. To resolve this, every dismiss now retires the lookup sequence and cancels its debounced search so late results cannot reopen the panel. Additionally, clicking anywhere outside the field and its body-portaled dropdown panel now correctly closes the panel, the Escape key is consumed to prevent it from also closing parent dialogs or slide panels, and destroying or rebinding the field properly cleans up in-flight searches and document listeners.
- **Explorer tab-navigation freeze and dynamic view cache collisions resolved** (`@memberjunction/ng-explorer-core`): Opening a saved view in its own tab previously froze the browser in an infinite loop. `NavigationService.OpenView` saved the prefixed resource type (`MJ: User Views`) in the tab configuration while the loaded view used `User Views`, causing `syncTabsWithConfiguration` to interpret every emission as a content change and repeatedly tear down and reload the tab. The reload check now uses `TabContainerComponent.IsSameResourceType` to correctly ignore case and strip the `MJ: ` prefix. Furthermore, dynamic views (such as omnibar navigation) share the `'dynamic'` record ID; the reload check now compares the tab's `Entity` so switching between dynamic entities (e.g. from `#Accounts` to `#Contacts`) reloads the grid instead of just changing the tab title. The `ComponentCacheManager` also folds the entity name into its cache key for the `'dynamic'` marker to prevent dynamic views from clobbering each other's cache entries.
- **Hierarchy tree package license corrected to BUSL-1.1** (`@memberjunction/ng-hierarchy-tree`): The `@memberjunction/ng-hierarchy-tree` package was added to the repository shortly after MemberJunction's transition to the Business Source License 1.1 on 2026-08-14, but mistakenly carried the default `ISC` license in its package metadata and shipped that way on npm in version 6.1.3. Its package manifest now correctly declares `BUSL-1.1` to align with the rest of the 6.x release line.

## Upgrade Notes
- **Cache-invalidation event row data is withheld by default** (`@memberjunction/server`, `@memberjunction/core`, `@memberjunction/core-entities`): To prevent connected clients from receiving row data they lack permissions to read, the `cacheInvalidation` subscription no longer broadcasts full row data. The `recordData` field is now only populated for entities explicitly listed in `cacheSettings.recordDataBroadcastEntities` on the server, which defaults to `[]`. To restore the previous behavior, add the desired entity names or `['*']` to this list. Under the default empty configuration, any remote save of an `AutoRefresh` entity in `BaseEngine` will now fall back to a full `RunView` reload of each matching config rather than executing a keyed read.
