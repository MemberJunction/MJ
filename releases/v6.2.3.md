# Archive engine paging, API key refresh, and RLS fixes

## TL;DR
A patch release for the certified 6.2 LTS line featuring multi-page archive execution, automatic API-key scope cache refreshing, and row-level security fixes for UI views. Additional updates cover MCP proxy rate limiting, integration schema key evolution, SQL Server error message sanitization, and primary key validation.

## Bug Fixes
- **Archive runs process every eligible record across multiple pages** (`@memberjunction/archiving-engine`, `@memberjunction/integration-test-suite`): `ArchiveProcessor` now fetches records in pages of `BatchSize` ordered by primary key until an empty page is returned, eliminating the previous limit where a run executed a single query capped by `UserViewMaxRows` (1,000 records by default) and stopped. Single-key entities page using `AfterKey`, while composite-key entities use key comparison seek logic over numeric or string primary key columns. Additionally, `BaseArchiveDriver.BuildEligibilityFilter` enables drivers to append SQL filters matching accepted records, allowing `DefaultArchiveDriver` in StripFields mode to filter out previously stripped records so they are not repeatedly loaded or counted as skipped on subsequent runs.
- **Failed archive runs record partial processed counts** (`@memberjunction/archiving-engine`): `ArchiveProcessor.ProcessEntity` now accumulates running totals as each batch page completes. When an archive run fails partway through processing an entity, `ArchivedRecords` retains the count of records processed on all completed pages prior to the error rather than losing progress statistics.
- **API key scope tables refresh automatically from the database** (`@memberjunction/api-keys`, `@memberjunction/api-keys-base`, `@memberjunction/core`, `@memberjunction/integration-test-suite`): `BaseEngine` background expiry ticks now re-read API-key scope, application, and key-binding records directly from the database every `scopeCacheTTLMs` (default 60 seconds) instead of reading the server cache. This ensures scope removals and application deactivations executed by other processes take effect within one TTL interval without requiring a server restart. Failed refresh ticks re-arm the timer instead of terminating the refresh loop, failed initial loads still initialize the timer, setting the interval to `0` stops background refreshes, and expiry timers use un-refed handles so they do not keep Node processes alive on shutdown.
- **Agent output links resolve safely for users with row-level security policies** (`@memberjunction/ng-conversations`): `ConversationAgentService` now queries agent output artifact links from `MJ: Conversation Detail Artifacts` using its own `RunView` instead of embedding a subquery over `[__mj].[vwConversationDetailArtifacts]`. Previously, `ClientClauseScreen` rejected the base-view subquery for users with row-filtered access to conversation detail artifacts, causing follow-up turns to lose prior agent output and fail continuity checks. The continuity check now calls the public `FindAgentArtifacts` method so subclass overrides are respected, and `FindArtifactVersionById` properly escapes ID values.
- **MCP server supports configurable proxy rate limits and trust proxy settings** (`@memberjunction/ai-mcp-server`): added `mcpServerSettings.trustProxy` and `mcpServerSettings.auth.proxy.rateLimit` configuration options (`windowMs` and `limit`). `trustProxy` applies directly to Express's `trust proxy` setting, enabling the OAuth proxy and `/mcp` endpoints operating behind CloudFront or a load balancer to track rate limits per client IP address rather than sharing a single 60-requests-per-minute limit across all callers.
- **OpenApp dependency validation uses installed package manifests** (`@memberjunction/open-app-engine`): `mj app install` and `mj app upgrade` now evaluate installed dependencies against the recorded manifest of the installed version rather than reading `mj-app.json` from the target app's default repository branch. This prevents unreleased dependency requirements on an upstream default branch from blocking local installations and upgrades.
- **Primary key validation rejects non-numeric input for numeric keys** (`@memberjunction/generic-database-provider`, `@memberjunction/postgresql-dataprovider`, `@memberjunction/sqlserver-dataprovider`): record loading, relationship lookups, and row-level security checks now validate numeric primary keys and raise an explicit error when non-numeric values are supplied, preventing raw database execution errors later in the pipeline. In addition, geocode cleanup after record deletion and relationship loading now escape single quotes in primary key values, and numeric `SET` values in SQL Server save statements are strictly validated as decimal or scientific number literals.
- **Artifact viewer opens records safely under row-filtered artifact permissions** (`@memberjunction/ng-artifacts`): fixed an issue where the artifact viewer threw "No artifact version found" for users with row-level security filters applied to `MJ: Artifact Versions`. The viewer now filters collection and conversation-link rows using the version IDs already retrieved in memory rather than running a subquery against the `Artifact Versions` base view that the API rejects for restricted users.
- **Realtime audio dock inert sheet controls hidden from navigation** (`@memberjunction/ng-conversations`): the closed "•••" compact sheet in the realtime call interface is now marked inert, preventing invisible control buttons (Type, Details, Camera, Share) from receiving keyboard tab focus, being announced by screen readers, or intercepting pointer clicks while hidden.
- **Video Studio render worker detects hoisted hyperframes packages** (`@memberjunction/video-studio-render-worker`): the render worker health check now resolves `@hyperframes/*` packages through Node's module resolution path, preventing false-positive missing package reports on hoisted pnpm or monorepo installations.
- **Integration schema refresh adds missing composite key columns** (`@memberjunction/integration-schema-builder`): schema evolution now appends missing key columns as nullable columns to existing integration tables when connector updates expand an object's primary key (such as adding `newsletter_id` to `id`). The refresh warns operators that existing rows must be cleared and fully re-synced, while preventing schema mismatches where uncreated key columns caused sync values to spill into `__mj_integration_CustomOverflow`. Key column comparison checks now compare SQL data types exclusively, preventing nullable key columns from being flagged as modified on subsequent refreshes.
- **SQL Server database provider returns sanitized THROW error messages** (`@memberjunction/sqlserver-dataprovider`): database operation failures caused by custom `THROW` or `RAISERROR` statements in triggers or stored procedures (SQL error numbers 50000 and higher) now return only the intended user message to callers. Previously, the provider appended full SQL statements and parameters to business error messages returned to clients; full query details continue to be written to server logs while standard engine errors (below 50000) retain full error context.
