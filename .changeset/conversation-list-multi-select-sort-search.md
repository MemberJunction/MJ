feat: the conversation sidebar gains modifier-click multi-select, bulk move/pin, sort buttons and a search clear button

Ctrl/Cmd-click toggles one conversation and Shift-click selects the range between it and the last row picked, both starting selection mode on their own; a range follows the order the list renders and never reaches rows hidden inside a collapsed folder or section. Both modifiers treat the conversation that is open as part of what you are picking: a Ctrl-click that starts a selection takes it along, so it moves and drags with the rows chosen beside it, and a Shift-click with nothing picked yet ranges from it, so one click highlights a span. A row picked with Ctrl takes over as the range start from there, and the open conversation is seeded only once — deselect it and it stays gone. Selection is shown the way a file manager shows it — the row itself carries an accent tint and a ticked checkbox, with no checkbox column taking up space; the open conversation keeps its solid accent fill, so a row that is both open and selected still reads as the open one. Picking rows needs no keyboard: a checkbox appears in a row's left padding when the pointer is over the row, and on every row while a selection exists; clicking it adds or removes that row. On touch a long-press on a row selects it and starts selection mode, after which a tap adds or removes a row. While a selection exists, the search row becomes a selection bar showing the count, with Pin or Unpin, Move to folder, Share, Delete and a clear button; the sort buttons stay in place so the list does not jump. Selection mode closes itself once the last row is deselected, and Escape leaves it; the ⋯ menu's "Select Conversations" entry is gone, since selection now starts from the list itself (a modifier-click, the row checkbox, a long-press, or Select All in the empty-space menu). The selection only ever holds rows on screen: Select All picks the visible rows, a search edit, a collapse or a grouping change drops the selected rows it hides, and a conversation that leaves the list leaves the selection. Clicking the empty space below the conversations drops the selection too, as clicking blank space in a file browser does. Every row action lives in one right-click menu, replacing both the per-row ⋯ menu's contents and the old bottom selection bar: right-clicking a selected row acts on the whole selection (a "3 selected" header, Pin, Unpin, Move to folder ▸, Delete 3), right-clicking any other row acts on that row alone and leaves the selection untouched, and the ⋯ button opens the same menu for touch and mouse-only users (on touch screens it is always shown). The menu stays inside the window, opening upward or moving left near an edge. The menu also carries Share, and it opens the same `mj-resource-share-dialog` the chat header and the dashboards use — one conversation or several. That dialog now accepts a set of resources through a new `Contexts` input: it merges everyone's access across them, labels a person whose access covers only some ("2 of 3") or sits at differing levels ("Mixed"), and applies every action — add, level change, removal — across the whole set. `Context` keeps working unchanged for a single resource, so dashboards and the chat header are untouched. Conversations you may not share — ones you neither own nor hold Owner access to, the same rule the chat header uses — are left out of the set and reported through the dialog's new `Notice` input, and Share is disabled when none of them qualify. The dialog leaves every resource's owner out of "Add people", and a retry after a partly failed save picks up where it stopped instead of repeating finished deletes or skipping unsaved rows. Right-clicking a folder offers New Subfolder, Rename and Delete — so the hover icons on folder rows are gone — and right-clicking empty space offers New Conversation, New Folder and Select All. Move and pin keep the selection so a second action can follow; delete takes only the deleted rows out of it, so deleting a row outside the selection leaves the selection alone. Bulk actions report any conversations they could not change. A selection can also be dragged: grabbing any selected row drags the whole selection onto a folder or onto Ungrouped, moving every one of them in a single batch, while grabbing an unselected row drags that row alone and leaves the selection untouched. A conversation row is a drop target for the folder it sits in, so dropping onto the conversations inside a folder files the drag there as well, and dropping onto an ungrouped conversation moves it out of its folder; conversations already in the destination are left alone rather than re-saved. A Date / Name button pair under the search box sorts the Pinned section, every folder and the Ungrouped list together — clicking the active button flips the direction — and the choice is persisted alongside the existing folder collapse state and group-by mode. The search box gains a clear button, and Escape inside it clears the query.

`ConversationEngine` gains `CanShareConversation` — the one share rule for the chat header and the sidebar — and `MoveMultipleConversationsToProject` and `PinMultipleConversations`, which save one conversation at a time so a single rejection cannot fail the batch, roll a failed conversation's fields back in memory, and emit the updated list once for the whole batch instead of once per conversation.
