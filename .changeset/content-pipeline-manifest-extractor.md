Content pipeline: a `Manifest` extractor expands a CSV or TSV that lists documents into child items, the way an archive expands into its members. Each row becomes a Content Item with `ParentID` set to the manifest, so a Sync leaves the rows alone unless the manifest is removed and a re-extraction retires rows no longer listed. A row with text is complete as listed; a row with only a link becomes an item at that link (relative links resolve against the manifest's address), which its own Extract fetches through the source's fetch and Access path. Which columns hold the link, text, title, date, decorator and a stable row key is configuration (`ExtractorOptions.Manifest`), and further columns map to item columns through `Columns`, including an IS-A extension's fields. A CSV is never a manifest by default: the extractor runs only when the extractor order selects it, and it refuses a manifest with no link or text column, a configured column the header lacks, an unreadable date, or more rows than `MaxArchiveMembers` (and, like an archive, reading with no limit configured). Supporting changes in the extractor contract: `ExtractRequest.Options` carries an extractor's `ExtractorOptions[<key>]`, layered from the source type's Configuration, the source's settings and Configuration, and the run's Options; a `ContentBlock` can carry its own `URL` and well-known `Fields` (a field's `Date` replaces the inherited one); `ExtractResult.IsContainer` keeps a one-block result a container; and the confidence scale gains `DiscoveredDecorator`.
