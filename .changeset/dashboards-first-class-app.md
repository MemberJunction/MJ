feat(explorer): Dashboards is its own application

Dashboards move out of Data Explorer into a first-class Dashboards app, and Home, the command palette and recents reach them directly. There is no schema change: the new application is metadata, shipped in the release's metadata sync.

- **Dashboards app** (`metadata/applications/.dashboards-application.json`: App Switcher navigation, default for new users) with four pages. **Overview** shows Continue, Favorites and Shared with you, plus Browse all and New dashboard. **Browse** lists the library through a rail of Library filters (All dashboards, My dashboards, Shared with me, Favorites, Recently opened) and the category tree. **Shared with me** lists the dashboards other people shared with the user. **Categories** shows the category tree with counts, creates categories and deletes empty ones that the user owns. Existing users get the app once, automatically, the next time Home loads; a user who later removes it keeps it removed. `@memberjunction/ng-bootstrap` registers the three new page classes.
- **Data Explorer** keeps Data and Queries. A dismissible banner on the Data tab points to the Dashboards app.
- **A dashboard opens in a workspace tab**, titled with the dashboard's name. Like any link, it replaces the current preview tab, so Back returns to the page it replaced (for example Home, a Dashboards app page or another dashboard) and Forward shows the dashboard again; Shift-click opens it in a separate tab, and so does a Ctrl or Cmd click on the Browse and Shared with me lists. A dashboard opened from a Dashboards app page is a tab of that app, so the app's header and pages stay in view; one opened from anywhere else (Home, the command palette, recents) is a tab of Home. A new dashboard, and a card's Edit action, open the dashboard in edit mode. The tab toolbar has a Favorite star and an Add to menu (Home tab, Pin card, Share). Editing happens in the tab: in edit mode it adds, configures and removes parts, Save stores them, and Cancel discards them. A tab that is not editing reloads when the dashboard's layout is saved elsewhere, and Edit starts from the latest saved layout, so one tab's save does not overwrite another's. Each Save also stores a small screenshot of the dashboard in `MJ: Dashboards.Thumbnail`, for the dashboard cards.
- **Home** gains a Dashboards section and dashboard tabs next to Overview. The section shows each dashboard live in a tile, at 80% of its size: the dashboard the user opened last (Continue), then up to two favorites. The tiles sit one, two or three side by side, by the section's width. The user drags the gap between side-by-side tiles to share the row's width, and the bar under a row to set the row's height (the arrow keys do the same, and a double-click resets); Home remembers these sizes for each user (`HomeApp.DashboardTileSizes`). A link in a tile's panel opens a record, a dashboard or a query as it does in a dashboard tab. A Browse all row under the tiles opens the Dashboards app's Browse page. The tabs are `MJ: Dashboard User Preferences` rows with `Scope = 'Global'`, edited in the Manage home dashboards dialog. The Dashboards section and the Pinned section both collapse, and Home remembers the choice for each user.
- **`mj-accordion-panel`** (`@memberjunction/ng-ui-components`): `Bare` now also drops the body fill and the row hover fill; on a device that can hover, pointing at the title or chevron gives both the brand color. A new `HeadingLevel` input wraps the toggle in a heading. Fix: the toggle's keyboard focus ring is drawn inside the header, so the panel no longer clips it; on a brand-colored header (the `primary` Variant, and the open sections of the Queries and Templates forms in `@memberjunction/ng-core-entity-forms`) the ring uses the inverse text color.
- **The command palette** lists matching dashboards (by name, description or category) in a Dashboards group; Enter opens the dashboard in place of the preview tab (Shift-click on a row opens a separate tab).
- **Recents include dashboards.** Opening one logs `MJ: Dashboards` access, and `RecentAccessService` maps prefixed entity names with the new `ResourceTypeForEntity` (`@memberjunction/ng-shared-generic`).
- **`mj-dashboard-browser`** (`@memberjunction/ng-dashboard-viewer`) gains `[FlatMode]`: one flat list of every dashboard it is given, with no folder scoping. Outside selection mode, a Shift, Ctrl or Cmd click on a dashboard now opens it with `OpenInNewTab: true` instead of selecting it; in selection mode those clicks still select, and a Shift range starts from the last dashboard clicked in selection mode.
- **New `@memberjunction/ng-shared` services:** `DashboardFavoritesService` (dashboard favorites in `MJ: User Favorites`) and `HomeDashboardTabsService` (the Home tabs). `HomeAppPinService.CaptureThumbnail()` takes an optional timeout.
- **`NavigationService.OpenDashboard` options** (`DashboardNavigationOptions`, `@memberjunction/ng-shared`): `applicationId` names the application the dashboard's tab belongs to (default: Home), and `openInEditMode` opens the dashboard in edit mode on the usual tab path (no forced new tab): the tab it opens in (the replaced preview tab, or a new tab) starts in edit mode, and a tab already open for the dashboard is focused and enters edit mode. The tab's component is also told through `DashboardEditModeRequested$`. The tab takes the request once with `TakeDashboardEditModeRequest(tabId, dashboardId, applicationId)`; the application check keeps a cached component of the same dashboard from another application's tab from taking it.
- **`mj-dashboard-viewer`** (`@memberjunction/ng-dashboard-viewer`) gains `HasNewerSavedLayout()`, `ReloadFromSaved()` and `UseSavedCopy()`: they compare with and show the dashboard's saved layout, and take a new copy of the dashboard without rebuilding. The package also adds `mj-dashboard-layout-preview` and `BuildDashboardLayoutPreview()`, a miniature of a dashboard's saved panel layout.
- **Moved export:** `DashboardPreferencesDialogComponent` is now exported from `@memberjunction/ng-dashboards`, not from `@memberjunction/ng-explorer-core`.
- **Agent context:** the Dashboards pages, the dashboard tab and Home report the new state to the agent. Each new agent tool reads, searches, filters or navigates; none creates, edits, shares or deletes a dashboard, a category or a Home tab.
- **Fix: saving a dashboard no longer reloads its tab in a loop.** The save froze the page, because each tab reload started the next one. The dashboard tab now reports a save as the dashboard's new name (the tab keeps its dashboard id and takes the saved name as its title), not as a record save, which rewrote the component's record id to `ID|<uuid>`. The tab container's reload check also accepts that form: the new `TabContainerComponent.IsSameRecordId` treats a single-field URL segment and its bare value as the same record. The loop was already on `next`.
- **Fix: `mj-dashboard-viewer` (`@memberjunction/ng-dashboard-viewer`) fills its box in a scaled host.** The viewer sizes Golden Layout to the layout container's layout size (`offsetWidth` / `offsetHeight`, which Golden Layout also reads when it resizes with the container), not its on-screen size, so a dashboard shown scaled (with CSS `zoom`, as in Home's tiles, or a transform) no longer lays out at the scaled size and leaves an empty band.
- **Fix: the panels of a dashboard in a tab no longer grow from zero height after Edit or Save.** The shell's stack animation now applies only to the shell's own layouts.
- **Fix: a dashboard loaded into DashboardEngine's cache (or any `MJ: Dashboards` object built with `GetEntityObject()` then `LoadFromData()`) now has the loaded values as its old values.** Before, its `UIConfigDetails` and `UserID` kept the defaults of a new dashboard. That made a clean dashboard look changed and made `Revert()` put back the defaults.
