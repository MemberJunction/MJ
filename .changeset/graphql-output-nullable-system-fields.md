fix(codegen-lib): nullable `__mj_` columns are nullable in GraphQL output types

`isNonNullableServerField` promised a value for every field that field-level security cannot strip (`IsUnrestrictableField`: primary keys and `__mj_` system columns) and ignored the column's own nullability. That holds for `__mj_CreatedAt` / `__mj_UpdatedAt`, which are NOT NULL, but not for `__mj_` columns the database leaves NULL — the geocoding columns `__mj_Latitude` / `__mj_Longitude`, NULL on every record that has not been geocoded, are the common case. CodeGen emitted them as non-null (`@Field(() => Float) _mj__Latitude: number`), so every single-record load of a record without coordinates failed with `Cannot return null for non-nullable field`, and a save committed in the database but reported failure because its returned record hit the same error.

An output field is now non-null only when it is both unrestrictable **and** NOT NULL in the database (`!AllowsNull && IsUnrestrictableField`). Primary keys and NOT NULL system columns stay non-null; restrictable columns stay nullable, as before. INPUT types are unchanged and keep deriving from `AllowsNull`.

Server types generated by 6.1.4 or earlier keep the non-null declaration until they are regenerated with this version: re-run CodeGen, and rebuild any package that ships generated server types.

Backport of the generator fix in #4635 (5fac5ccb82) from `next`.
