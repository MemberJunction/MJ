Integration Test TestType — graduation Phase 4: engine-level fixture lifecycle + new coverage (RLS, dataset cache, aggregates).

- **Engine-invoked suite-scoped fixtures (the net-new D6 mechanism).** New `SuiteFixtureContext` type in `@memberjunction/testing-engine-base` (keyed by `SuiteRunID`, carries `Data` + `CreatedRecords`); additive no-op `BaseTestDriver.SetupSuite()` / `TeardownSuite()` hooks; `TestEngine.RunSuite` now resolves the suite's driver(s) once, runs `SetupSuite` before the tests and **guarantees** `TeardownSuite` + `updateSuiteRun` in a `finally` (fires on pass, fail, a thrown `Execute`, and `Timeout`); the context threads into every `Execute` via `DriverExecutionContext.fixtures`. Suite hooks fire only for `mj test suite` (a suite run exists), not standalone `mj test run`.
- **Thrown-`Execute` hardening (D-FX2).** A driver `Execute` that throws is now converted to a final `Status='Error'` `TestRun` (with the error message) instead of being left stuck `'Running'` — so a buggy/edge-case driver can't wedge the run and suite teardown stays consistent.
- **RLS / multi-user cache isolation (the #1 security item).** New `rls-isolation` bundle: **RLS1** proves two distinct effective RLS clauses yield distinct `GenerateRunViewFingerprint` outputs (the `rls:<hash>` segment — a leak would collide), **RLS2** proves the server superset slot does not cross-serve (User B is a separate cold slot, no A-scoped rows leak); a client-transport `rls-isolation-client` bundle carries **RLS3** (smart-cache validation, needs MJAPI). The two-user fixture is **discovered** (never minted) from `provider.RowLevelSecurityFilters` + the user cache, with a no-op teardown and graceful skip-as-pass when the DB has only RLS-exempt admins.
- **Dataset cache + aggregates coverage.** New `dataset-cache` bundle (DS1 cold→populate / warm-serve via the `IsDatasetCached` transition, DS2 status APIs) — assertions are behavioral because the dataset cache uses the provider's own `LocalStorageProvider`, separate from the instrumented `LocalCacheManager` (verified live). New `aggregates-cache` bundle (AGG1 proves `Aggregates[]` participates in the fingerprint / aggHash, AGG2 proves `AggregateResults` round-trips through a warm cache hit).
- **Single source of truth preserved.** The new check functions live once in `@memberjunction/testing-integration` and are consumed by both the `IntegrationTestDriver` (which threads the discovered RLS fixture + per-selector config into the shared `IntegrationCheckContext`) and three new standalone `tsx` scripts (`rls-isolation`/`dataset-cache`/`aggregates-cache-tests.ts`). Metadata seeds IT06/IT07/IT08 + their deterministic-suite memberships.
- Validated live against a real DB: `mj test suite "Integration Tests — Deterministic"` runs IT01/IT02/IT06/IT07/IT08 (IT03 excluded by Skip membership), 5/5 passed, per-check `ResultDetails` persisted as a bare `OracleResult[]`. Unit tests: engine fixture-lifecycle meta-tests (cleanup on throw/timeout, teardown-throw swallowed, per-run isolation, thrown→Error) + RLS discovery and the `GenerateRunViewFingerprint` RLS-divergence invariant.
