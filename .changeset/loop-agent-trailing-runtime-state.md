Add an opt-in trailing placement for Loop agent runtime state so provider prompt caches survive across iterations. Today the Loop agent system prompt renders the current date/time, Scratchpad State and Payload at its tail, and because those blocks change every iteration the provider's prefix cache breaks before it reaches the conversation history; measured on Sage the cached share of input was 37% and the entire history was re-read on every step. A new Loop agent prompt param `volatileStatePlacement` (`systemPrompt`, the default, or `trailingMessage`) gates those blocks out of the template and replaces them with a static pointer paragraph, while `BaseAgent.preparePromptParams` builds the same content into a `<mj-runtime-state>` fragment appended as the final `user` message; at send time the fragment tag literal is escaped in every history message so no tool result or user text can pose as framework state. A companion param `specializationPlacement` (`auto`, `systemPrompt`, `trailingMessage`) relocates the agent's own child prompt into the fragment when it contains volatile placeholders, so a per-iteration date in a child prompt cannot silently reintroduce the cache break. The default rendering is byte-identical to today and locked by a snapshot test. `AIPromptRunner` exposes `RenderChildPromptTemplates` publicly for the relocation path, and `AgentChatMessageMetadata` gains a `volatileState` flag so provider adapters can recognise the fragment. Live on Sage with Gemini 2.5 Flash the system prompt was identical across every iteration and the cached share rose to 68–85% with 60–80% lower prompt cost. Metadata: two new properties on the Loop agent type's `PromptParamsSchema`.
