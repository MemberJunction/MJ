Open Apps can declare `publicPages` in `mj-app.json`: pages the host serves before sign-in, at `/p/<slug>`. A page answers the addresses under its slug only with `"subPaths": true`. An entry with `"role": "error"` and a `scope` is an error page for a folder under `/p/` (empty scope: all of `/p/`). The manifest rejects reserved slugs such as `login`, `auth` and `admin`. `mj app install` and `mj app upgrade` write the entries to a top-level `publicPages` array in `mj.config.cjs` and fail when another installed app owns a slug; `mj app remove`, `enable` and `disable` remove or toggle them. `mj codegen manifest --open-app-client-bootstrap` now also writes the host's page list, `public-pages.generated.ts`, beside the class manifest, and warns when the host's `main.ts` does not call `StartExplorer()`. The new `mj explorer postbuild --dir <build folder>` is the host's `postbuild` script: it runs the service worker cache check and writes `public-pages/<slug>.html` for each page, with its title, link preview tags, a robots tag and a Content Security Policy that allows only the site's own scripts, and without the map library tags. It also writes `public-pages/_fallback.html`, with the same policy and a `noindex` robots tag, for the `/p/` addresses that have no page file. When the build folder has a `staticwebapp.config.json` (Azure Static Web Apps), it also adds a rewrite for each page and for the fallback file.
