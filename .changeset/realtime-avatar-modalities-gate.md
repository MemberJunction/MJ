A realtime model shows an agent's avatar only when its `MJ: AI Model Modalities` Video/Output row allows video and the endpoint profile of its driver renders avatars. A row with `IsSupported` false turns video off: the session prep asks the driver for no avatar, logs one line, and the call's status says `endpoint` ("this voice model can't show an avatar"); a model with no row is left to its driver's profile, as before. The rows are read from the AI engine's cache (`ReadRealtimeVideoOutputRow`, `RealtimeModelShowsAvatar`). A co-agent with video on, when no model is named (no runtime pick and no `realtime.modelPreference`), takes the first candidate that shows an avatar, trying each model's keyed vendor rows by Priority (`RealtimeClientSessionService.ResolveAvatarRealtimeModel`, `ListRealtimeVendorsForModel`); when none does, it keeps the model it would have taken, audio only, with one log line. A server-side session (`PrepareClientSessionInput.ServerSide`, set by `BaseAgent`'s bridge prep) gets the preference only when its host publishes the avatar into a room (`AvatarDelivery: 'room'`). Integration check RD18 drives the gate through real metadata: Gemini 3.8 Live on Vertex AI asks for the avatar, a tagged model on the same endpoint whose row has `IsSupported` false asks for none, and without that row it asks again.
