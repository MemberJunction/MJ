A source with a page renderer renders only what is HTML, optionally only when a plain fetch finds the page empty, and can tune how the renderer loads a page.

When a page is rendered is a `BasePageRenderPolicy`, selected by `PageRenderMode` (`Always` or `WhenEmpty`; anything else is `Always`). Extract and the website crawl ask the same policy, and read every setting from a source's layers in one order (a blank string counts as unset, so a lower layer still decides), implemented once in `ConfigurationLayers.ts` (`ConfiguredValue`, `ConfiguredPath`, `MergedWebsiteConfiguration`, `TuningFor`): run, then source, then its `SourceSpecificConfiguration`, then the source type. Extract's own settings, `AccessResolver`'s driver key and credential mapping, and `Tuning` now use it; **`Tuning` changes order**: a source's own `Configuration.Tuning` now outranks its `SourceSpecificConfiguration.Tuning` (before, the reverse), as every other setting does. Every registered class in content-pipeline-base resolves through one `ResolveRegistered` helper. `DiscoverRequest` gains `RunConfiguration` and `TypeConfiguration` for it. The empty-page threshold is `Tuning.EmptyPageTextChars` (default 200).

Extract and the website crawl no longer hand every http(s) address to `PageRenderer`: a HEAD (or the plain response) says what the address is, and a document file (`IsDocumentContentType`, in network-utils: PDF, Word, Excel, PowerPoint, OpenDocument, an image...) is fetched plainly; any other answer, `application/octet-stream` included, is rendered as before. `Configuration.PageRenderMode: 'WhenEmpty'` fetches each page plainly first and renders only an empty, script-only page (`LooksLikeEmptyPage`, a scan linear in the page's length) or one the site refused to the plain fetch (`RendersAfterRefusal`: a 401, 403 or 5xx, not a 404, 410 or 429); the default `Always` keeps today's behaviour for HTML. A rendered page reaches the Html extractor labelled UTF-8, so the site's own `<meta charset>` does not mis-decode it. `Configuration.PageRendererOptions` (`WaitUntil`, `WaitSelector`, `WaitSelectorTimeoutMs`, `ScrollToBottom`, `UserAgent`) reaches the renderer as `PageRenderRequest.Options`; the `Headless` renderer honours them, and takes Chromium launch arguments from `HeadlessPageRenderer.LaunchArgs` or `MJ_HEADLESS_CHROMIUM_ARGS` (e.g. `--no-sandbox` in a container). Extract's plain fetch sends `Website.UserAgent` and refuses a body past `Website.MaxResponseBytes` as a lasting error.
