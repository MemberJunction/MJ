A `required` scope dimension that resolves to nothing — an expansion query with no rows, an empty caller set, a blank string, `null` — now refuses the search with a `ScopeDimensionError`, the same way a narrowing that meets to nothing already did. Previously only an *unresolved* (`undefined`) required dimension was refused, so an empty bound passed through to the lane templates; under the `{% if x | length %}` idiom an empty set removes the clause, and a template without an `{% else %}` then ran unbounded. Dimensions explicitly declared `inheritanceMode: 'cascading'` (where empty is meaningful; their template must carry an `{% else %}<column> IS NULL` branch, as the guide now says) and dimensions that are not `required` are unaffected. The message says whether the caller sent an empty value, the declared `defaultValue` is empty, or nothing is reachable for the user, so an agent that sent an empty argument is told to fix its call rather than that the user has no access. Behaviour change to note: a user whose bound is legitimately empty now gets a refused search (an error result) rather than an empty success — or a widened one, where the template dropped the clause — and in a multi-scope search that refusal fails the whole call, as every `ScopeDimensionError` already does.
