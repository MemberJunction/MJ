A search scope can now declare its own permission over-fetch multiplier in `ScopeConfig.permissionOverfetchFactor` (the guide already listed the key; nothing read it). The engine resolves the factor as the caller's `SearchParams.PermissionOverfetchFactor`, else the largest factor across the resolved scopes (a scope that declares none counts as the engine default, so one scope's low factor never lowers a neighbour's), else the engine default (2), and holds it to 1–20 whatever the source. The factor is resolved after the result-cache lookup, and `streamSearch`'s per-provider partial events are capped to the caller's `MaxResults`, so a larger factor cannot multiply what a stream client is shown before the permission pass. A scope whose lanes are trimmed heavily by late permission checks can ask providers for more candidates without every caller having to know to pass the parameter. Also fixed: a non-finite caller value or engine default (`NaN`, `Infinity`) used to flow through `??` into the provider `topK`; it is now treated as absent. Scopes that declare nothing behave as before, and so do callers passing a value within 1–20; a caller value above 20 is now clamped to 20, and a numeric string is now ignored rather than coerced (no caller in the repository passes one).
