Workflow Run Console — realtime runner & debugger (v1, for iteration)

Extends the Phase 5 runtime overlay (view B of phase5-overview-v1.html) into a live console: frames instead of polling, breakpoints and stepping via claim gating, edge verdicts, claim visibility, and stall diagnosis. Same canvas, same workflow, four states of one surface. Lives in the Workflows app as its run view. D18: users see steps and paths; engine vocabulary stays in the collapsible engine strip.

A · Live run — frames, not polling

The run view driven by taskGraphFrames. A running Agent step drills into its child run's live stream (the existing agent pipeline) right on the node. The selected step's inspector shows its claim and live activity; the engine strip at the bottom ticks once per dispatcher pass. A breakpoint is set on a downstream step (red dot).

C · A stuck run diagnosing itself

The hardening review's signature failure — "the graph looks fine while a run strands silently" — made visible. Two real defect classes on one canvas: a path that can't be evaluated because its origin step was skipped and produced nothing (holds forever today), and a step whose worker vanished mid-claim (invisible today). The banner names both; the inspector explains and offers the safe ways out.

D · After it settles — replay

A settled run scrubs through time on the same canvas (the master-clock pattern from the agent-run flow views), reconstructed from step timestamps and the run's frame log. Step markers on the scrubber are colored by outcome; dragging replays statuses, edge decisions, and the activity feed in sync.
