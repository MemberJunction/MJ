Create Workflow — the front door

The screen that replaces today's save-the-agent-record-first requirement. Per D18 nothing here says graph, DAG, node or Flow Agent — those survive in metadata and dev docs only. This screen lives in a new Workflows Explorer app, not inside the AI app: a business user automating something does not look under "AI", and D19 exists precisely because the editor is currently buried.

Open questions from phase5-overview-v1 — now answered

  1. ① Concurrency cap placement → toolbar, not per-node. It is a property of the workflow ("run at most N steps at once"), not of any one step. Per-node placement would imply each step carries its own limit, which the engine does not model — maxConcurrentSteps lives in the flow's params bag.
  2. ② Recovery-path style → dashed amber covers recovery only. Validate-rejection routes get no special colour because they are not a route: a rejected graph never runs, so there is nothing to draw. Rejections surface in the validation banner, which is where an author can act on them.
  3. ③ Run view → right-panel activity feed. A bottom timeline strip competes with the canvas for horizontal space, which is the axis a fan-out graph needs most. The feed also reads chronologically top-to-bottom, matching how someone follows a run in progress.
  4. ④ Save as Workflow from chat → name it inline, then offer the editor. One field and a Save button in the card; a "Open in editor" secondary. Dropping straight into the editor makes saving feel like a commitment to more work, which is exactly the friction that stops a good one-off plan becoming reusable. Triggers are not asked for here — a saved workflow defaults to On demand, because the moment of saving is about capture, not scheduling.
  5. ⑤ Minimap & palette → collapsed by default under 1100px. Both are navigational aids for a graph large enough to need them; on a narrow viewport they cost more canvas than they return.

B — From a past run

C — Save as Workflow, from a chat plan card (answers ④)

Name it inline and save. "Open in editor" is available but secondary — making the editor mandatory turns a two-second capture into a task, which is what stops good one-off plans becoming reusable. No trigger is requested: saving is capture, not scheduling.
